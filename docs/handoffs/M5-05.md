### Validator changes

| Rule                        | What it checks                                                                                                                                                                                                                                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **4-word runs**             | No 4-word run appears more than 5 times across every `kind=sentences` list. Words are lowercased and punctuation is stripped from word ends. The problem is reported at the 6th use, with the first one cited.                                                                                    |
| **Biome key sets**          | A list tagged `biome=<id>` may use only the keys taught up to that biome (`BIOME_NEW_KEYS` / `biomeKeys()`), and its `keys` tag may ask for nothing more. This is the check the M3-02 reviewer asked for. It needed no change to the existing lists.                                              |
| **Sparkstone symbols**      | `- _ ( ) : @ # / = + *` are allowed in phrases and sentences only in `biome=sparkstone` lists. Sky Citadel comes after Sparkstone in `BIOME_ORDER`, but it doesn't get them, because Sparkstone is a side branch (README §8.5).                                                                   |
| **Digits in phrases**       | Phrases may hold digits, for `5 red mushrooms`. The biome key check keeps digits out of the lists before Marsh.                                                                                                                                                                                   |
| **Sentence length by band** | Sprout and `all`: 40 chars. Miner: 70. Builder: 90.                                                                                                                                                                                                                                               |
| **Sentence folder**         | The validator reads `src/content/wordlists/` and `src/content/sentences/` as one set: one duplicate check per band, one registry. `--sentences DIR` (CLI) and `sentencesDir` (API) read another sentence folder. With `--dir` alone, only that folder is read, so the old fixtures are unchanged. |
| **`#` comment lines**       | A comment must be `# text`, with a space. A line such as `#gems: 3` is read as a comment, so the item is silently dropped. This happened to six of my own code strings before I caught it.                                                                                                        |

## Decisions

- **Sentences live in `src/content/sentences/`**, as the card's Owns says, and register in the one `POOL_IDS`. The alternative was to put them in `wordlists/`, outside the card's Owns. I chose to widen the `pools.ts` glob by one path and the validator by one folder. Ids are `<biome>-sentences-<band>`, so they can't clash with word-list ids.
- **"Tagged by key set and length".** Every sentence file has a `keys=` tag (the biome's full cumulative set) and a `biome=` tag. Length is set by `band`, and the validator now enforces it (Sprout ≤ 40, Miner ≤ 70, Builder ≤ 90). I didn't add a `length=` tag, because that would mean editing `TAG_NAMES` in the loader (contracts §5).
- **Reading tags.** As in M3-02: Sprout `grade2`, Miner `grade4`, Builder `grade6+`. The validator has no `grade1`.
- **Apostrophe.** The `'` key arrives in Crystal Caverns. The biome key check now enforces this: no contractions in Frosty, Mines or Marsh content.
- **`/` in Caverns.** README §8.4 puts `, . /` in Caverns, so `/` is a Caverns key. Sentences can't use it, because it isn't in the sentence character set. Only Sparkstone lists use it (`yes/no`, `on/off`, `day/night`).
- **Colons and hyphens** are in the sentence character set from M1-10. They are Sparkstone keys, so the Caverns and Citadel sentences use neither, and Citadel sentences have no hyphenated words.
- **No items start with `#`.** The card's example `#blocks: 12` is written `total #blocks: 12`. A bare `#blocks: 12` can't be an item in this format, because it would be read as a comment.
- **Story.** The Big Lantern on Home Island has grown dim. Friends gather one crystal each from the Mines, the Marsh, the Caverns and the Sky Citadel to light it again. Sparkstone is an optional side trip. The sentences use generic friendly creatures from `PLAN.md` §7.3: the Frost Pup, a Moss Golem, a Slimeling, cave bats, crystal crabs, a Lantern Fish, and a new sky owl named Zephyr. A rotating cast of kids from many cultures appears, plus a few grown-ups (Grandpa Eli, Aunt Mei, Grandma Noor) and a cave guide, Pearl.
- **Left out on purpose** (full list in `SOURCES.md`):
  - Slang: `shroom`, `croak`, `stool`, `nuts`, `shady`, `hung`.
  - Body words: `plump`.
  - Products and IP: `minecart` as one word, `glowstone`, `piston`, `switch`, `sprite`. The owl isn't called `Nimbus`, a famous fictional broom.
  - Character names: Alexa, Siri, Cortana, Bing, Elsa, Luca, Milo, Finn, Zane.
  - Fear and harm: `tank`, `zap`, `shadow`, `battlement`.
  - Every fire and explosion word, including the whole `expl...` family. Sentences say "travel" or "look" instead of "explore".
  - Drinking readings. I checked word pairs too: no flasks, no glass of anything, and "we had warm soup" instead of "drank".
  - Pressure words: `seconds left`, `hurry`, `wrong`.
  - Boss names: they live only in i18n.
- **The code strings avoid** real programming idioms (`if`, `count = count + 1`, `Hello, world`). They contain no file paths, URLs or `word@word` strings that look like email addresses. They also leave out the words `variable`, `program` and `hashtag`. `knob`, `slash` and `hash` are blocklisted, so the sentences call them "the / sign" and "the # sign".
