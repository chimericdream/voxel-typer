# M3-01 Curriculum validator and doc generator

Status: done

## What changed

- `tools/validate-curriculum.ts` (new): the validator. `npm run tool -- validate-curriculum` prints
  `<lesson or biome>: [rule] message` and exits 1 on a problem. CI's `content` job already runs
  every `tools/validate-*.ts`. Its pure entry point is `validateCurriculum({ lessons, pools,
  messages, inProgress? })`. The `node:fs` loaders (`loadLessons`, `loadPools`, `loadMessages`)
  feed it under tsx.
- `tools/gen-curriculum-doc.ts` (new): writes `docs/curriculum.md`, one table per biome with these
  columns: lesson, English title, new keys, kind (plus tags), mode, length, targets, and a sample
  (Miner band, seed 1). `--check` exits 1 when the file is stale. The tables come out padded the
  way Oxfmt writes them, so `oxfmt --check` passes on the file.
- `docs/curriculum.md` (new, generated).
- `src/content/lessons/types.ts`: **implemented `allowedKeysFor`**, which was a stub that the
  M1-01, M2-12 and M2-13 handoffs left for this card. The rule is the same as Mine's `allowedKeys`
  (a test checks the two agree on every shipped lesson), plus `opts.sparkstoneUnlocked` from
  contracts §6. The signature is unchanged.
- `tests/unit/content/curriculum.test.ts` (new, 36 tests): the shipped lessons pass, each rule
  fails on a fixture, the tool loaders match the Vite aggregators, the CLI exits 0, the
  `allowedKeysFor` cases, and **`docs/curriculum.md` is current** (the test renders it and
  compares, so `npm test` and CI fail when it is stale).

### Rules

Generation calls the pure generator the way Mine mode does. It imports `lengthPlan`, `poolsFor`,
`EST_WPM` and `TARGET_LATENCY` from `src/modes/mine/logic.ts`. Allowed keys come from
`allowedKeysFor`, and `keyWeights` gets the lesson's `newKeys` as focus and no stats. Each run uses
`createRng(seed)` for seeds 1–10, for each of sprout, miner and builder.

| Rule           | Checks                                                                                                                                                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `unique-id`    | No two lessons share an id.                                                                                                                                                                                                                    |
| `id-format`    | The id is `<biome>-<order>`, with order padded to 2 digits.                                                                                                                                                                                    |
| `order`        | Each biome's orders are 1…n, with no gap or repeat.                                                                                                                                                                                            |
| `new-keys`     | Each new key is one char and not a space. No key is introduced twice in the whole curriculum. A lesson introduces only keys its biome teaches (`BIOME_NEW_KEYS` from `validate-wordlists.ts`, M5-05). A finished biome introduces all of them. |
| `review-keys`  | Review keys were introduced before the lesson: they are allowed keys and not the lesson's own new keys.                                                                                                                                        |
| `allowed-keys` | Generated text uses only allowed keys. A space may appear only inside `phrases` and `sentences` targets.                                                                                                                                       |
| `variety`      | ≥ 20 distinct targets per band over 10 seeds, and every seed gives targets. For `letters`: min(20, number of allowed keys).                                                                                                                    |
| `real-words`   | `words`, `phrases` and `sentences` lessons: ≥ 70 % of the generated targets are pool items, not the syllable fallback, for every band.                                                                                                         |
| `pools`        | Every pool id a lesson names exists.                                                                                                                                                                                                           |
| `mastery`      | Exactly one `mastery` lesson per biome. It is last, or second to last right before the boss lesson. For a biome in `IN_PROGRESS_BIOMES`, a missing mastery lesson is a warning, not a problem.                                                 |
| `boss`         | At most one `boss` lesson per biome, and it is last. The `boss` tag goes with `mode: "boss"` and only with it.                                                                                                                                 |
| `space`        | **(orchestrator, beyond the card)** Each biome has a lesson that practises the space bar: kind `phrases` or `sentences`, or `mode: "practice"`.                                                                                                |
| `title`        | `titleKey` names an English string.                                                                                                                                                                                                            |

## Decisions

- **In-progress biomes.** The card wants exactly one mastery lesson per biome, but Meadow 1–6 has
  none and must pass. `IN_PROGRESS_BIOMES` (in the tool, currently `meadow`) turns two problems
  into a warning or a skip for those biomes: a missing mastery lesson, and keys of the biome not
  yet introduced. Every other rule still applies.
- **"Every new key introduced exactly once"** covers both halves: no key twice, and every key the
  biome teaches, for a finished biome. The key table is M5-05's `BIOME_NEW_KEYS`. I imported it
  rather than copying it, so the word-list and curriculum checks share one source.
- **Letters lessons and the 20-target floor.** A letters target is one key, so meadow-01 can never
  give 20 distinct targets. For letters, the floor is min(20, allowed keys): every allowed key must
  show up.
- **Space rule.** `phrases`, `sentences` or `mode: "practice"` count as space practice. `words` in
  Mine don't, because of decision 81.
- **Boss rule** (beyond the card): the tag and the mode must go together, as README §8.3 and the
  M3-03 card describe. This makes "the boss lesson" one thing, which the mastery placement rule
  depends on.
- **The doc's sample band is Miner** (band scale 1), and targets are separated by `·` when they
  contain spaces. Biome names in the doc come from PLAN.md §3.1. They are a doc-only table, not
  i18n.
