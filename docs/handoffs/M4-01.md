## What changed

- `src/render/models/rig.ts`: `compileRig(def)` puts the parts in parent-first order and binds each anim track to a slot in a flat `Float32Array` pose (9 floats per part: pos delta, rot, scale). `sampleTrack` does per-track linear interpolation, clamping, loop wrap and steps. No three.js and no clock.
- `src/render/models/animator.ts`: `Animator`: `play(name, { loop?, fadeMs?, speed?, restart?, onEnd? })`, `stop({ fadeMs? })`, `update(dtMs)`, plus `animating` and `current`. Crossfade is `CROSSFADE_MS = 120`. `onEnd` fires once. Reduced motion and bad timing input are handled here. No three.js.
- `src/render/models/validate.ts`: `modelErrors(x: unknown)` lists `path: message` problems. `isVoxelModel` is the type guard and `parseModel` throws. It checks everything in the schema, plus the cross-references a schema can't express. There are no casts.
- `src/render/models/schema.json`: a draft-07 JSON schema for `*.model.json`. A model file may set `"$schema"` to point at it.
- `src/render/models/geometry.ts`:
  - `partGeometry` builds one box per part with its origin at the pivot, per-face atlas UVs (`cropSpan`), vertex colours and a `vtTex` weight.
  - `modelMaterial` makes the one shared `MeshLambertMaterial`.
  - With a map, `patchModelShader` lets `vtTex` choose per vertex between the atlas texel and white, so flat and tiled parts share one material and one program. It throws, naming the anchor, if a three.js chunk it patches is missing or appears twice.
- `src/render/models/build.ts`: `buildModel(def, atlas, opts?)` and `buildModelInstanced(def, count, opts?)`.
- `src/render/models/driver.ts`: `createModelDriver(loop)`. It is one loop system that updates the animating models and keeps the loop awake only while one still moves. A disposed model drops out at once.
- `src/render/models/index.ts`: re-exports.
- `tests/unit/models/`: 121 tests.
  - `anim.test.ts` (47)
  - `build.test.ts` (32)
  - `driver.test.ts` (11)
  - `schema.test.ts` (31)
  - `helpers.ts` (fixtures and the draw-call counter)
  - `box-critter.model.json`, an original sample creature: a green box with stubby legs, dot eyes and a grass-tile tuft. It has 9 parts and `idle`, `walk`, `hit` and `defeat`. The helper and the fixture sit beside the tests, outside the `*.test.ts` Owns glob.

## API as built

```ts
buildModel(def: VoxelModel, atlas: ModelAtlas | null, opts?: { reducedMotion?: () => boolean }): ModelHandle
interface ModelHandle {
  root: THREE.Group;                                   // card API
  play(anim: string, opts?: PlayOptions): boolean;     // card API; false for an unknown anim (never throws)
  update(dtMs: Ms): void;                              // card API; time in ms, from the caller
  setTint(color: THREE.ColorRepresentation | null): void; // card API; multiplies the material colour (darkens only)
  dispose(): void;                                     // card API
  stop(opts?: { fadeMs?: Ms }): void;                  // extra: fade back to rest
  readonly animating: boolean; readonly current: string | null;
  part(name: string): THREE.Mesh | undefined;          // extra: attach points, plate anchors
  bindDriver(link: DriverLink | null): void;           // used by the driver: { wake(), disposed() }
}
type PlayOptions = { loop?: boolean; fadeMs?: Ms /* default 120 */; speed?: number; restart?: boolean; onEnd?: () => void };

buildModelInstanced(def, count, opts?: { atlas?: ModelAtlas | null; reducedMotion?: () => boolean }): InstancedModelHandle
// root, count, place(i, at, yaw?, scale?), setVisible(i, v), isVisible(i), play(i, anim, opts),
// stop(i), current(i), update(dtMs), setTint(i, color | null), part(name), animating, bindDriver, dispose()

createModelDriver(loop: Pick<RenderLoop, "addSystem" | "wake">): { add(model): () => void; size; dispose() }
```

A mode does: `const driver = createModelDriver(scene.loop); driver.add(buildModel(def, scene.atlas(), { reducedMotion }))`, then `scene.three.scene.add(model.root)`.

## Decisions

- **Units and frames:** see the §8.4 text under "Contract change request / Questions". **+z is the front.** The critter's head sits at +z. `place(i, at, Math.atan2(dx, dz))` turns it toward `(dx, dz)`, which matches the front `Object3D.lookAt` gives a non-camera object. A test pins this.
- **Texel density:** a face shows one atlas texel per model pixel, centred on whole texels. A 4-px tuft shows the middle 4×4 texels instead of a squashed tile. Faces over 16 px stretch the tile.
- **One material per model with a `vtTex` shader patch**, rather than two materials, so a model that mixes flat and tiled parts costs one program and one draw call per part. `setTint` multiplies that material's colour, and each model has its own material, so tints don't leak between models. A tint can only darken; a white hit flash needs another approach (M4-04).
- **The crossfade starts from the pose at the moment of the switch,** frozen, and the new anim runs during the blend. It works the same whatever was playing, including a half-finished fade.
- **Rotations blend per Euler component.** That's fine for the small angles mobs use, and cheaper than quaternion slerp.
- **An unknown anim name makes `play` return false; it doesn't throw.** A mode asking a pet for a `hit` it doesn't have must not crash a child's game.
- **Bad timing input never throws either.** `speed ≤ 0` (or not finite) means "no playback", as described under N3, so nothing waits forever and the loop can idle.
- **Instances start hidden,** and a hidden instance is paused. `count` is a pool's capacity. `frustumCulled = false`, as in M2-05's particles, because instances move.
- **`onEnd` fires only for a clamped anim** that reaches its end, never for a loop or for an anim that was replaced first.
- **Validation is stricter than the type:** a part needs `color` or `tile`, at most 32 parts (M4-03 asks for 6–14), and model ids and anim names are lowercase-dashed. The guard is what the code trusts; the schema is for editors and the repo-wide test.
- **Reduced motion:** a looping anim snaps to its first frame and the loop goes idle. One-shot anims still play, because they are feedback and their `onEnd` drives game logic.

## Reduced-motion hook (for M3-07 and the modes)

`buildModel(def, atlas, { reducedMotion: () => boolean })`, and the same option on `buildModelInstanced`.

- The function is read on every update, as `SceneOptions.reducedMotion` is.
- When it returns true:
  - looping anims (`idle`, `walk`, any `loop: true` anim) snap to their first frame, including when the flag turns on mid-loop, and then report `animating = false`, so the driver lets the render loop idle;
  - one-shot anims (`hit`, `defeat`) still play and fire `onEnd`;
  - crossfades still run (120 ms).
- The modes should pass the same resolved function they give the scene. I didn't touch `src/a11y/*` or `motion.css`.
- **Turning the flag on:** the driver sees the held loop as animating until the snap is written, so it needs a frame. A mode with mobs is already drawing frames.
- **Turning the flag off:** the loop resumes when something wakes the render loop.
- **For M4-03:** keep `hit` and `defeat` free of big spins and of flashing over 3 Hz (PLAN §4.6). The critter's `defeat` (scale up, then to 0, with a 4 px rise) is a good model.

## Contract change request / Questions

- No frozen contract changed. `VoxelModel` (§8.4) fits as written. The builder API comes from the card.
- **For the orchestrator, additive.** This is the §8.4 units text, final, to copy under the code block. It is the reviewer's draft, with +z confirmed and a line on hidden instances:

  > **Units and frames** (decided in M4-01):
  >
  > - All lengths (`size`, `pivot`, `offset`, `pos` key values) are **model pixels**; 16 model pixels = 1 block (`MODEL_UNIT = 1/16`), the same density as a 16×16 tile.
  > - `pivot` is a point in the part's own box, measured from the box's **minimum corner** (`[0,0,0]` is the −x −y −z corner, `size` the opposite one). The part rotates and scales about its pivot.
  > - `offset` places the part's pivot in its parent's frame, measured **from the parent's pivot**. A root part (no `parent`) is measured from the model origin: the ground point under the creature, y = 0 at the floor, **+z the facing direction** (the front `Object3D.lookAt` gives; yaw `atan2(dx, dz)` faces `(dx, dz)`).
  > - A child inherits its parent's animated transform, scale included.
  > - Animation key values are **deltas from rest**:
  >   - `pos` adds pixels to `offset`;
  >   - `rot` is an Euler rotation in **degrees**, applied in three.js `'XYZ'` order;
  >   - `scale` multiplies (rest `[1,1,1]`).
  > - Key times `t` are ms from the anim start, non-decreasing, within `[0, durationMs]`. Two keys at the same time make a step.
  > - Tiled faces show one atlas texel per model pixel, centred on whole texels (`floor((16 − n) / 2)`). Faces over 16 px stretch the tile.
  > - Runtime (`src/render/models/`): `buildModel(def, atlas, opts)` and `buildModelInstanced(def, count, opts)`; `update(dtMs)` takes time in ms from the caller. A `speed` or `dtMs` that isn't positive and finite never stalls an anim.

- Not in §8.4, but named in the card: `buildModelInstanced(def, count)` takes a third `opts` argument (with `atlas`), because tiled parts need the atlas. A call with only `(def, count)` still works, and tiled parts then show grey.
