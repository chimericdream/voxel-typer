## What changed

- `src/render/models/rig.ts`: `compileRig(def)` puts the parts in parent-first order and binds each anim track to a slot in a flat `Float32Array` pose (9 floats per part: pos delta, rot, scale). `sampleTrack` does per-track linear interpolation, clamping, loop wrap and steps. No three.js and no clock.
- `src/render/models/animator.ts`: `Animator`: `play(name, { loop?, fadeMs?, speed?, restart?, onEnd? })`, `stop({ fadeMs? })`, `update(dtMs)`, plus `animating` and `current`. Crossfade is `CROSSFADE_MS = 120`. `onEnd` fires once. Reduced motion is handled here too. No three.js.
- `src/render/models/validate.ts`: `modelErrors(x: unknown)` lists `path: message` problems. `isVoxelModel` is the type guard and `parseModel` throws. It checks everything in the schema, plus the cross-references a schema can't express. There are no casts.
- `src/render/models/schema.json`: a draft-07 JSON schema for `*.model.json`. A model file may set `"$schema"` to point at it.
- `src/render/models/geometry.ts`: `partGeometry` builds one box per part with its origin at the pivot, per-face atlas UVs, vertex colours and a `vtTex` weight. `modelMaterial` makes the one shared `MeshLambertMaterial`. With a map, a small `onBeforeCompile` patch lets `vtTex` choose per vertex between the atlas texel and white, so flat and tiled parts share one material and one program.
- `src/render/models/build.ts`: `buildModel(def, atlas, opts?)` and `buildModelInstanced(def, count, opts?)`.
- `src/render/models/driver.ts`: `createModelDriver(loop)`. It is one loop system that updates the animating models and keeps the loop awake only while one still moves.
- `src/render/models/index.ts`: re-exports.
- `tests/unit/models/`: 81 tests.

  - `build.test.ts` (18)

  - `box-critter.model.json`, an original sample creature: a green box with stubby legs, dot eyes and a grass-tile tuft. It has 9 parts and `idle`, `walk`, `hit` and `defeat`. The helper and the fixture sit beside the tests, outside the `*.test.ts` Owns glob.

## API as built

```ts
buildModel(def: VoxelModel, atlas: ModelAtlas | null, opts?: { reducedMotion?: () => boolean }): ModelHandle
interface ModelHandle {
  root: THREE.Group;                                   // contract
  play(anim: string, opts?: PlayOptions): boolean;     // contract; false for an unknown anim (never throws)
  update(dtMs: Ms): void;                              // contract; time in ms, from the caller
  setTint(color: THREE.ColorRepresentation | null): void; // contract; multiplies the shared material colour
  dispose(): void;                                     // contract
  stop(opts?: { fadeMs?: Ms }): void;                  // extra: fade back to rest
  readonly animating: boolean; readonly current: string | null;
  part(name: string): THREE.Mesh | undefined;          // extra: attach points, plate anchors
  bindWake(fn: (() => void) | null): void;             // used by the driver
}
type PlayOptions = { loop?: boolean; fadeMs?: Ms /* default 120 */; speed?: number; restart?: boolean; onEnd?: () => void };

buildModelInstanced(def, count, opts?: { atlas?: ModelAtlas | null; reducedMotion?: () => boolean }): InstancedModelHandle
// root, count, place(i, at, yaw?, scale?), setVisible(i, v), isVisible(i), play(i, anim, opts),
// stop(i), current(i), update(dtMs), setTint(i, color | null), part(name), animating, bindWake, dispose()

createModelDriver(loop: Pick<RenderLoop, "addSystem" | "wake">): { add(model): () => void; size; dispose() }
```

A mode does: `const driver = createModelDriver(scene.loop); driver.add(buildModel(def, scene.atlas(), { reducedMotion }))`, then `scene.three.scene.add(model.root)`.

## Decisions

- **Units.** Lengths are model pixels: 16 make one block, the same density as a 16×16 tile. Whole-pixel creatures are easy to write by hand.
  - `pivot` is measured from the box's minimum corner.
  - `offset` places the pivot in the parent's frame, measured from the parent's pivot. For a root part it's measured from the model origin, the ground point under the creature, with y = 0 as the floor.
  - Anim values are deltas from rest: `pos` in pixels, `rot` as XYZ Euler angles in **degrees**, `scale` as a multiplier.
- **Texel density:** a face shows one atlas texel per model pixel, centred, so a 4-px tuft shows the middle 4×4 texels of its tile instead of a squashed tile. Faces over 16 px stretch the tile.
- **One material per model with a `vtTex` shader patch**, rather than two materials, so a model that mixes flat and tiled parts costs one program and one draw call per part. `setTint` multiplies that material's colour, and each model has its own material, so tints don't leak between models.
- **The crossfade starts from the pose at the moment of the switch,** frozen, and the new anim runs during the blend. This is simple, it's the same whatever was playing (including a half-finished fade), and over 120 ms it looks the same as blending two running anims.
- **Rotations blend per Euler component.** That's fine for the small angles mobs use, and cheaper than quaternion slerp.
- **An unknown anim name makes `play` return false; it doesn't throw.** A mode asking a pet for a `hit` it doesn't have must not crash a child's game.
- **Instanced instances start hidden.** `count` is a pool's capacity, and a hidden instance draws a zero matrix. `frustumCulled = false`, as in M2-05's particles, because instances move.
- **`onEnd` fires only for a clamped anim** that reaches its end, never for a loop or for an anim that was replaced first.
- **Validation is stricter than the type:** a part needs `color` or `tile`, at most 32 parts (M4-03 asks for 6–14), and model ids and anim names are lowercase-dashed. The guard is what the code trusts; the schema is for editors and the repo-wide test.
- **Reduced motion:** a looping anim holds its first frame, and the loop goes idle. One-shot anims still play, because they are feedback and their `onEnd` drives game logic.

## Reduced-motion hook (for M3-07 and the modes)

`buildModel(def, atlas, { reducedMotion: () => boolean })`, and the same option on `buildModelInstanced`.

- The function is read on every update, as `SceneOptions.reducedMotion` is.
- When it returns true:
  - looping anims (`idle`, `walk`, any `loop: true` anim) hold their first frame and report `animating = false`, so the driver lets the render loop idle;
  - one-shot anims (`hit`, `defeat`) still play and fire `onEnd`;
  - crossfades still run (120 ms).
- The modes should pass the same resolved function they give the scene. I didn't touch `src/a11y/*` or `motion.css`.
- Turning the flag off mid-loop takes effect on the next update. The driver only notices once something wakes the loop. In practice that's at once, because a mode with mobs is already drawing frames.
