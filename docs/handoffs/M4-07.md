A child opens **My Island** from the world map and builds on their Home Island by typing. A block's
name puts that block in their hand, `put` places it at the cursor, `dig` takes a block back,
directions move the cursor and `undo` steps back. No key is ever an error, and nothing can be lost:
every block dug goes to the inventory and every edit can be undone.

To try it: `npm run dev`, then `/?profile=meadow-done-miner&screen=island&nosave=1` (a Miner with
planks and cobble), `fresh-sprout` (an empty bag and the key-cap palette) or `veteran-builder` (an
island that won't open).

North is −z, east is +x. Typed directions always mean the island's compass; the HUD says which
one is at the top of the screen ("North is at the top"). Water can't be placed, so `water` is not a word.

**A key that doesn't fit doesn't go in.** This is Mine's "stay" rule, which every band already
knows from the Meadow: the letter is not added, a soft thud plays, and the line says what would fit.
So the line always holds the start of a real command, and a Sprout never has to find Backspace.

## Prefix ambiguity (for the pedagogy review)

The card's rule: a word runs by itself when it is a whole command and no longer command starts with
it; otherwise Space or Enter runs it.

- **`blue` and `bluebell`** are the one pair in today's registry. `blue` shows a Space key cap
  beside the line and waits; Space or Enter arms blue wool; typing on to `bluebell` arms the
  flower, which runs on its last `l`.
- **Shared starts are not ambiguous.** `put` / `puff` / `planks`, `dig` / `dirt` / `down`, `up` /
  `undo`, `log` / `lantern` / `leaves`: each runs on its own last letter, because none is the whole
  start of another.
- **Directions always wait,** because `east 3` starts with `east`. Enter moves one step. Space
  makes room for a number, and the number runs on the digit.
- **Numbers are one digit, 1 to 9.** With two digits, `east 1` would have to wait in case a `2`
  followed, while `east 3` ran at once. One digit means every number runs the moment it is typed.
  A longer walk is `east 9` twice, or a held arrow key.
- A unit test checks the rule for every word in the vocabulary, and a property test checks that
  the line is always the start of something the parser knows.

**Decision for the reviewer:** a bare direction costs one more key than other words (`east` +
Enter). The alternative, running `east` on its `t`, would make `east 3` impossible to type.

## The Sprout picture palette

- The top of the screen shows up to **six blocks: the ones the player owns most of**, each as a
  picture of the block with its count.
- **Slots hold still.** A block keeps its slot while the player owns any; the block in hand keeps
  its slot even at 0. A freed slot is filled by the most-owned block not yet shown.
- **Sprout** sees `KeyCap` chips under each picture, one per letter of the block's **short code**:
  the first letters of its name, three or more, as few as tell it apart from every other word.
  23 of the 27 blocks are three letters: `dirt` → `dir`, `planks` → `pla`, `cobble` → `cob`.
  `grass` → `gras` and `gravel` → `grav` (they share `gra`); `blue` stays `blue` and needs Space, and `bluebell` is `blueb`.
- A code runs on its last letter. **The rest of the name may still be typed** and is taken quietly,
  so a Sprout who types the whole word `dirt` sees nothing odd. If those letters turn out to start
  another word (`pla`, then `north`), they are given back to the line.
- **Miner and Builder** see the block's whole word under the picture and type it in full.
- The block in hand is outlined, and named at the bottom right ("In your hand: Dirt").
- A new player with an empty bag sees "Type dig to pick up a block. Then type put!". The first block
  dug goes into the hand.

**Question for the pedagogy review:** the card asks for 3-letter codes, and PLAN §3.2.4 says
"commands are real words". `dir` and `cob` are not words. I followed the card and kept the whole
word typeable. If real words matter more for Sprouts, the fix is content: shorter `typedName`s.

## Never lose an island

- `openIsland` runs inside a try/catch. If it throws (a wrong grid size, or broken run-length
  data), the mode has **no editor**: it loads nothing, takes no keys, plays no sound, and **never
  sends a save**, by autosave, pause or leaving. `Profile.island` stays byte for byte as it was.
- The child sees a calm panel: "Your island is resting. We could not open your island this time.
  It is safe, just as you left it. Ask a grown-up for help. To leave, press Esc, then pick Back to the map."
- `createIsland` is called only when `profile.island === null`. That fresh island is written only
  after the first edit, so visiting an island never writes.
- The `veteran-builder` fixture's island is 16×8×16 with a zero-length run, so it is the damaged case in the unit tests
  and the e2e. A second unit test uses a 48×32×48 grid with bad run-length data.
- There is no "start a new island" button. A grown-up path to reset a damaged island needs the
  parent gate and is a product decision; see Questions.

## Saving, and `found`

- The island and the inventory are always written together, as one `IslandPatch`.
- **Autosave:** after 30 s of play time and on every pause, only when the editor is dirty. A pause
  is also what a hidden or closing tab produces, so a closed tab loses at most the keys since the
  last pause. An idle island tab never writes.
- **Leaving** (Pause → Back to the map, or any route change) calls the mode's `leave()`: the mode
  ends its typing session and hands the host the last patch and the summary, and the host writes
  both in one save. A visit with no edit and no typed word writes nothing.
- **The host applies both onto the current profile,** not the copy from when the visit began. The
  old `applyResult(r.profile, …)` path would have saved the pre-visit island over the autosaved one.
- **`found`:** `withIslandPatch` writes `found: foundBlocks(profile)` when the profile has none,
  from the inventory before the first island change. It never touches an existing `found`. Dug
  blocks go to the inventory only.
- **Two tabs:** not made worse, and not fixed. Every save still writes the whole profile, so a tab
  that builds can overwrite lesson progress saved by another tab since it loaded. Builder narrows
  the window only by not writing when nothing changed.

## The practice session

- A session with `mode: "builder"`, `end: manual`, `stars: 0`, no `lessonId`.
- A command's keys are fed to the session when the command runs, as one target (`"east 3"`). A key
  that didn't fit is a slip on the letter it was typed for. Letters taken back with Backspace leave
  no trace. The session is paused between commands, so `activeMs` is typing time only.
- Space as `put`, the habit space, the arrows and the camera keys type no word.
- A pause drops a half-typed word, so its keys are never fed without their first letters.
- The host folds it with `applyResult(profile, null, …)`: key stats, bigram stats, history and the
  session counter, with no lesson record. Builder is not in `BASELINE_MODES`, so it never moves the
  star baseline.
- Engine events go on the bus, so the break reminder and live badges work. End-of-lesson badges are
  not evaluated: Builder is not a lesson.

## Decisions

- **The card's `oak` is `planks`.** No block has the typed name `oak` (`oak-log` is `log`,
  `oak-planks` is `planks`). The tests type `planks`.
- **`put` and `dig` reach past the cursor's cell** (first free cell above, first block below). A
  cursor that sits in the air or inside the ground would otherwise answer "nothing here" to most
  first tries.
- **The camera turns in quarter turns,** so "left" is always one compass direction and the arrows
  can follow the screen. It follows the cursor only once the cursor is 5 cells from the look-at
  point. Glides snap under reduced motion (the rig does this).
- **The cursor frame breathes** 5 % in size every 1.4 s, and holds still under reduced motion and
  `?freeze`. It is drawn a second time, faintly, through everything, so it can be found behind a
  tree.
- **A flower needs a block under it** that is not another flower ("Flowers need a block under
  them."). Digging the block under a flower leaves the flower, as M4-06 allows.
- **Builder brings its own key listener** for arrows and Page keys. The frozen input contract turns
  arrows into menu controls, which never reach a running mode, and drops Page keys. The listener
  acts only while the mode is live, skips handled events and chords, and lets a held key repeat.
- **The play host calls `leave()`,** an optional method on its own `InspectableMode`. `ModeInstance`
  is unchanged.
- **Saves travel on the bus** (`builder:save`), which contracts §7.2 allows for namespaced events.
- **Hints stay 5 s** or until the next key that fits. The welcome line stays until the first key.
- **The HUD component lives in `src/modes/builder/`** (the card's Owns). `check-ui-literals` does
  not scan that folder; every string there goes through `t()`.
