### Branch protection command (run after this PR merges)

```sh
gh api -X PUT repos/chimericdream/voxel-typer/branches/main/protection --input - <<'EOF'
{
  "required_status_checks": { "strict": true, "checks": [{ "context": "ci-ok", "app_id": 15368 }] },
  "enforce_admins": false,
  "required_pull_request_reviews": null,
  "restrictions": null,
  "allow_force_pushes": false,
  "allow_deletions": false
}
EOF
```

`strict: true` means branches must be up to date. `app_id` 15368 is GitHub Actions, so only a check made by Actions counts as `ci-ok`. `enforce_admins: false` lets the admin bypass. Check it with `gh api repos/chimericdream/voxel-typer/branches/main/protection --jq '{checks: .required_status_checks.checks, strict: .required_status_checks.strict, admins: .enforce_admins.enabled, force: .allow_force_pushes.enabled, delete: .allow_deletions.enabled}'`.

## Decisions

- **Based on `main`, PR targets `main`.** #89 was already squash-merged when I started (`1c25755`, same tree as `origin/task/M0-01`, I checked with `git diff`), so I branched from `origin/main` and opened the PR against `main`, not `task/M0-01`. Nothing needs retargeting.
- **Snapshot commits get checks through a dispatch.** `update-snapshots.yml` ends with `gh workflow run ci.yml --ref <branch>`, because `workflow_dispatch` is the one event a `GITHUB_TOKEN` push may start. Check runs belong to the commit, so the dispatched run puts `ci-ok` on the PR's new head. The dispatched run finds the PR by branch for the sticky comment and skips dependency review (a baseline commit changes no dependencies).
- **Dependency review is skipped while the dependency graph is off.** It is off on this repo, and `dependency-review-action` errors without it. The `deps` job probes `GET /repos/{owner}/{repo}/dependency-graph/sbom` (404 while off) and skips the review with a warning; `npm audit --omit=dev` always runs. I was not allowed to change the repo setting myself. When the owner turns the graph on, the review starts running with no CI change.
- **Content checks discover tools by name:** each `tools/validate-*.ts`, then `tools/i18n-keys.ts`, then `tools/gen-curriculum-doc.ts` followed by a dirty check on `docs/curriculum.md`. There is also a JSON syntax check over tracked `src/**/*.json`. I tested each path locally with fake tools (failing validator, stale doc, bad JSON) and with nothing present.
- **The `docker` job enforces M0-05's spec once a `Dockerfile` exists:** non-root `USER`, `HEALTHCHECK`, `/` 200 with `no-cache`, `X-Content-Type-Options`, `Referrer-Policy`, `Cross-Origin-Opener-Policy`, CSP header with `frame-ancestors 'none'`, `Permissions-Policy` denying camera, microphone and geolocation, SPA fallback, `immutable` on hashed `/assets/*.js`. `/sw.js` (JavaScript, `no-cache`) is checked only when the `dist` artifact has `sw.js`, because the SPA fallback answers `/sw.js` with `index.html` before a service worker exists.
- **Coverage thresholds switch on through a repo variable:** `ci.yml` passes `vars.COVERAGE_THRESHOLDS` into the env, so M1-GATE runs `gh variable set COVERAGE_THRESHOLDS --body 1`, or flips `enforceThresholds` in `vitest.config.ts`. Either way nobody edits CI.
- **e2e image tag:** the `build` job reads the version from `node_modules/@playwright/test/package.json` and passes it to the e2e matrix as an output. `update-snapshots.yml` and `nightly.yml` read it from `package-lock.json`, so they don't need an `npm ci` first.
- **No cache for the Playwright image.** The pull took 19 s per shard on this PR. Saving the multi-GB image to the Actions cache and restoring it would take longer. npm is cached through `setup-node` in every job, including inside the container.
- **The sticky comment uses `gh api` in a step** (find the comment by marker, then PATCH or POST), not a third-party action. Fork PRs are skipped, since their token is read-only.
- **No third-party actions** besides `actions/*` and `github/codeql-action`. All are pinned to a full SHA with the version in a comment. The actionlint Docker image is pinned by digest.
- **`/update-snapshots` refuses `main` and fork PRs**, and only comments from `github.repository_owner` (chimericdream) trigger it. That account is both the owner and the orchestrator here.
