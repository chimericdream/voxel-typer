## What changed

  avatar. "Change a player" turns on change mode, where picking a card opens a dialog with
  **New name**, **Change group** and **Delete player**. Each of the three asks a grown-up first.
  Delete also needs the player's name typed (case and edge spaces don't matter). Damaged profiles
  show as "A lost player" cards, which a grown-up can delete. A profile from a newer game shows,

## Decisions

- **The grown-up gate is one hook.** `useGrownUpGate()` renders its question inside the caller's
  dialog. A second modal `<dialog>` would fight the first one's focus trap. The placeholder asks
  "A grown-up needs to say yes. Grown-up, is this OK?" with Yes and Not now. A child can press
  Yes, so it is a speed bump, not a lock, until M3-08.
- **Change mode, not a button on every card.** Kids mostly pick, so the arrow keys still step
  through just the cards plus three buttons. Escape leaves change mode before it leaves the
  screen.
- **A damaged card opens the delete offer directly,** even outside change mode, because picking
  it can't do anything else.
- **Changing group keeps a grown-up's tweaks.** A band setting (text size, keyboard, hands, calm
  mode, read-aloud) follows the new band only while it still has the old band's default value.
- **Delete confirm:** the typed name is compared without case or edge spaces, since a 6-year-old
  may not find Shift. Every letter must be there.
- **Avatar render:**
  - The shared renderer draws into its own `WebGLRenderTarget`, between frames, and then gets
    back its render target, clear colour, alpha and `autoClear`.
  - Faces are flat-shaded through vertex colours, so the portrait doesn't depend on the scene's
    lights.
  - The read-back converts linear to sRGB and supersamples 3×3 per pixel for smooth edges.
  - `@/render/avatar` (three.js) loads only after `app.scene()` succeeds, so lite mode never loads
    it.
  - Visiting Profiles now creates the shared scene, which the map needed next anyway.
- **The avatar model is built from the face grid.** The face is a 1-deep layer of boxes, the
  head behind it is hair (skin at the jaw), with a mustard tunic, leaf-green collar, brown belt
  and trousers. A test pins the tunic as warm, not light blue (IP rule).
- **PROVISIONAL `VoxelModel` geometry:**
  - One unit is one face pixel, y is up, and the model faces +z.
  - `offset` is the box's min corner and `pivot` is the joint, both in model space.
  - The contract doesn't define these. M4-03 (mobs) should confirm them or change them; only
    `buildModelGroup` reads them.
