# M1-12 i18n runtime

Status: done

## What changed

- `src/i18n/format.ts` (new): an in-house minimal ICU formatter. It handles `{name}` params, `{n, plural, =N {…} one {…} other {…}}` with `#` (nesting allowed), and ICU apostrophe quoting. Parsed patterns are cached. Malformed syntax stays as literal text and never throws.
- `src/i18n/index.ts`: implements `t()` and `setLocale()` and removes the stubs. Lookup follows dotted paths through nested tables with own-property checks only (`common.toString` is missing, not a function). A key missing from the current locale falls back to English.
- `tools/i18n-keys.ts` (new): an oxc-parser scanner over `src/**/*.{ts,tsx}`, skipping `src/i18n/**`. It reports **missing** keys (a static `t()` key with no English text) and **unused** keys. Run it with `npm run tool -- i18n-keys [--root DIR]`. It exits 1 on any problem.
- `tests/unit/i18n/format.test.ts`: tests for interpolation, plurals and escaping.
- `tests/unit/i18n/t.test.ts`: tests for lookup, missing keys in dev and in production, and `setLocale`.
- `tests/unit/i18n/keys.test.ts` + `tests/unit/i18n/fixture/`: runs the scanner on a fixture tree, through the API and as a CLI, then on the real repo.
- `src/i18n/en/common.ts`: unchanged.

## Decisions

- Dev vs production uses `import.meta.env.DEV`, read on every call so tests can stub it.
- Production fallback: the card says "English text or the key's last segment". `t` tries the current locale, then English, then the last segment. A key that has English text is never "missing", whatever the locale.
- `en-XA` has no table yet, so `setLocale("en-XA")` shows English. M6 builds the pseudo-locale, either as a table in `tables` or as a transform.
- Escaping follows ICU's default apostrophe mode. A `'` quotes only before `{`, `}`, or `#` inside a plural, so "Let's go" needs no escaping. `''` gives one `'`. Param values are never parsed. Nothing is HTML-escaped, because Preact escapes text when it renders it.
- A missing param leaves `{name}` in the text. It doesn't throw, so the bug shows on screen.
- Plural categories always use `Intl.PluralRules("en")`, since every locale is English. `#` prints the param as given.
- The scanner counts three kinds of use:
  1. Static `t("…")` calls. These are checked for missing keys.
  2. ``t(`prefix.${x}`)``. Every key under the static prefix counts as used.
  3. Any string literal equal to a defined key, such as `Lesson.title: MessageKey` in content data.

  Without (2) and (3), keys stored as data would show up as false "unused" reports.

- `common.appName` and `common.notAffiliated` have no screen yet, so they're listed in `PENDING_KEYS` in `tools/i18n-keys.ts`. Each entry names the work that will use it. Pending keys may be unused. A pending key that becomes used, or is deleted, fails the check (`stale-pending`), so the list only shrinks. The list applies to the repo root only, not to `--root` fixtures. CI's `content` job runs this tool as soon as it exists, so the allow-list has to live in the tool, not in a test.

## Notes for downstream tasks

- Exports added beyond the contract: `formatMessage` and `parseMessage` from `src/i18n/format.ts`. The tool exports `scanSource`, `compareKeys`, `definedKeys`, `scanTree`, `loadTables` and `checkI18nKeys`.
- Nested tables work: `{ biome: { meadow: "Meadow" } }` gives `ns.biome.meadow`.
- Write keys as literals: `t("ns.key")`, or ``t(`ns.prefix.${id}`)`` with a non-empty static prefix. `t(variable)` can't be checked. A key held as data must be the full literal string somewhere in `src/`.
- Whoever first uses `common.appName` or `common.notAffiliated` (the title screen or footer) must delete its entry from `PENDING_KEYS` in `tools/i18n-keys.ts`. The CI `content` job and `keys.test.ts` both fail until they do.
- The key check runs in CI's `content` job (`npm run tool -- i18n-keys`) and in `npm test` (`keys.test.ts`). It isn't part of `npm run lint`.
