# M4-10 No-failure invariants and M4 E2E

Status: done (CI's "green twice" is in the PR checks below)

The no-failure rule (PLAN.md §1 pillar 2) now has one home, `tests/unit/invariants/`. Its
properties run Mine, Night Defense, Builder, the placement test and remedials through the real
play host and save store, plus the two-tab rebase path. The M4 e2e suite in `tests/e2e/m4/` plays a
night at 15 WPM to dawn, checks the loot on My Blocks, and stamps a house that survives a reload.

## What changed

- `tests/unit/invariants/never-less.ts` (new, test helper): `expectNeverLess(before, after,
  { building })` is the one check every property shares. Nothing goes down: the inventory (or, for
  Builder, the island plus the bag, per block), `found`, unlocked biomes, every lesson record's
  best stars, WPM, accuracy and plays, and badges. A lesson record never disappears either.
  `totals` and `liveTotals` give the per-block sum of island and bag.
- `tests/unit/invariants/results.test.ts` (new): `applyResult` and `applyPlacement` with **any**
  `ModeResult`. Stars are 0–3, loot is any block (including unknown ids) with junk counts (0, −1,
  fractions, NaN, ∞), and the placement `extra` can be malformed. The results are chained across
  shipped lessons, remedials, free play and placement on six fixtures, 300 runs. Each step checks
  that the loot is added exactly once and that the session counts once. The island and badges are
  untouched. A remedial or free play writes no lesson record and unlocks nothing. A second
  property adds the save store's round trip after every step.
- `tests/unit/invariants/modes.test.ts` (new): the real Mine and Defense modules in the real play
  host on a fake scene, saving into a memory `SaveStore`. The key streams have any mix of right
  keys, wrong keys, Space, Backspace, Enter, capitals and unused keys, with 20–2500 ms gaps. After
  the stream the session is played out. The stored profile has nothing less, and the loot is
  added exactly once. Mine runs every shipped Mine lesson × three bands (30 runs). Remedials run
  12 times: no lesson record, no unlock, and the history keeps the remedial id. Defense plays
  three nights × three bands, calm on and off, 10 runs. Each run is a whole night to dawn.
- `tests/unit/invariants/builder.test.ts` (new): the real Builder module in the play host, the real
  store, any run of typed commands. The commands include every vocabulary word, blueprint names,
  `put`/`dig`/Undo, directions with counts, Enter, Backspace, junk, autosaves, pauses and
  revisits (leave, then load from the store and open again).
  - After each step, the stored copy adds up per block: to this visit's opening sum (the island as
    opened, with any ring it was owed, plus the bag) or, before the visit's first save, to the last
    visit's.
  - `found` never changes, and `progress` is untouched.
  - The runs cover `meadow-done-miner`, `fresh-sprout` and `island-builder` (which stamps `house`,
    `well` and `tower` and grows a ring), with three bags, 30 + 15 runs.
  - **A damaged island is never written:** for two kinds of broken island, the island and the bag
    stay as they were and `saveProfile` is never called, whatever is typed, autosaved or paused
    (20 runs).
- `tests/unit/invariants/two-tabs.test.ts` (new): the rebase path (M3-FIX-9).
  - A fake `updateProfile` stands in front of one shared copy. Before each save, "the other tab"
    makes 0–4 changes (loot, a lesson finished there, a setting). `derive` runs on each newer copy
    as the real retry does, and sometimes on the stale base first. Only the last result is
    written.
  - Every lesson, remedial and placement result is applied **exactly once**: the session counter,
    history and plays go up by one each, and the bag and `found` are the start plus the other
    tab's loot plus this result's. `derive` never changes the copy it is given (150 runs).
  - For Builder: autosaves and the last save, with real editor moves. The island plus the bag
    equals the start plus the other tab's loot, the island is this tab's, and `found` gets only the
    other tab's loot (80 runs).
  - When the other tab changed the island itself, its island and bag stay, plus anything found
    since (40 runs).
- `tests/e2e/m4/helpers.ts` (new): `night(page)` (the Defense `lockOn` view, as in
  `defense.spec.ts`), `fixtureJson`, `seedRecord` and `storedRecord` for the game's IndexedDB
  store, and `comeBackAs` / `pickPlayer` (reload, Players screen, pick).
- `tests/e2e/m4/night.spec.ts` (new): `meadow-done-miner` on `birch-08`. `createKid` (the
  `typeLikeAKid` press at 15 WPM, 6 % slips, seed 15) types whatever the field asks for, and waits
  while the field is empty. The night must show "The sun is up! The camp is safe!" and reach
  Results with stars ≥ 1, more than 3 words, and loot ≥ words. Then Results → Map → **My Blocks**:
  each block the night dropped has an `owned` slot, the bag holds the fixture's count plus the
  loot, and the slot's `data-count` matches. Timeout 15 min. Locally the night took 2.0 min.
- `tests/e2e/m4/island.spec.ts` (new): the real IndexedDB store, with no `?profile` or `?nosave`.
  - `island-builder` is written into the store, and "Ivy" is picked on the Players screen.
  - On My Island the island grows its Birch ring and the plans read `well house tower`. The child
    types `house`, then `east 6` and `glass put`, then leaves. The store then has the island
    (`expansions: 1`), the bag (cobble 20, clay 8, glass 1, planks 14) and one more history entry.
  - After a reload and a fresh pick, the island opens (not damaged) with the same counts and no
    second ring. Leaving again writes the same grid and bag.

## Decisions

- **Invariants through the play host, not only the pure fold.** The card says "for any `ModeResult`
  and any key stream". `results.test.ts` covers any `ModeResult`. `modes.test.ts` and
  `builder.test.ts` cover any key stream, with the real modes, the real host and a real store,
  so the save path is covered too. Both are fast because the modes run headless.
- **The Defense property in `tests/unit/modes/defense/defense.test.ts` stays.** That file is not
  in this card's Owns. The new one goes further: through the host and store, with remedials and
  Enter keys. The M4-04 note offered lifting it, and the orchestrator can delete the old one
  later if they want one copy.
- **Two helper files in the owned folders** (`never-less.ts`, `tests/e2e/m4/helpers.ts`), like
  `tests/e2e/m3/helpers.ts`. The Owns globs name only `*.test.ts` / `*.spec.ts`.
- **The night spec types with `createKid`, not `typeLikeAKid` itself.** `typeLikeAKid` types a
  known string. A night's next key changes as mobs come and go, so the spec reads it before each
  press. It is the same press function, rhythm and slips.
- **The island round trip seeds IndexedDB directly**, as `import-export.spec.ts` does, because
  `?profile=` always uses a throwaway memory store (`src/main.ts`).
- **No screenshot baselines.** A night runs on real time and no two runs draw the same frame
  (M4-04). The island and My Blocks already have baselines from M4-08 and M4-09.
