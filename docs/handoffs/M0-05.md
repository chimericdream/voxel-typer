## Decisions

- **nginx, not Caddy.** `nginxinc/nginx-unprivileged:alpine` is built to run as non-root on 8080 and keeps all its writes under `/tmp`, so it works with a read-only root filesystem without any changes. `caddy:alpine` runs as root by default and wants writable `/data` and `/config` for its own state and TLS storage, which we don't need (Tailscale terminates HTTPS). nginx's one trap, that a location's own `add_header` drops every inherited header, is handled by a rule (headers only at server level, per-path values through `map`) that the unit test enforces.
- **Brotli is not enabled.** The stock nginx image doesn't include the brotli module. Text is gzipped on the fly. Adding brotli would mean building nginx or switching image, which isn't worth it for a LAN game. M6-06 can revisit it.
- **The CSP header mirrors `index.html` exactly, plus `frame-ancestors 'none'`.** Permissions-Policy denies `camera`, `microphone`, `geolocation`, plus `payment` and `usb` (nothing in the game uses them). Not `fullscreen`, since the game may use it.
- **Only `/assets/` is immutable.** Everything else, including future `public/` files such as fonts, is `no-cache` (revalidated with ETag, so a 304 is cheap). The test fails if a `public/assets/` directory appears, because files there would be unhashed but cached for a year.
- **`publish.yml` triggers.** `workflow_run` on `CI` (completed, branch `main`); the job runs only when `conclusion == 'success'`, `event == 'push'`, `head_branch == 'main'` and the head repo is this repo, so PR runs and forks can never publish. It checks out `workflow_run.head_sha`, not the default branch head. CI doesn't run on tags, so for `m*`/`v*` tag pushes the job first asks the API for a successful CI run of the tagged commit from a push to `main`, and fails with a clear message if there isn't one (tag only after CI on main is green, or re-run the job).
- **`:edge` only moves to main's current head.** If CI runs finish out of order, an older commit gets its `:sha-<short>` tag but doesn't overwrite `:edge`. With `concurrency` and `cancel-in-progress: false`, GitHub keeps one queued run per group, so when several merges land at once the middle ones may never get a `:sha-` tag. That's acceptable for previews.
- **Token permissions:** workflow default `{}`; the job has `contents: read` (checkout), `actions: read` (the tag path's CI-run lookup) and `packages: write`. Checkout uses `persist-credentials: false`.
- **Multi-arch for free.** The build stage is pinned to `$BUILDPLATFORM` (the `dist/` output is the same on every architecture) and the final stage has no `RUN`, so the arm64 variant needs no QEMU. `provenance: false` keeps the image index to the two real platforms (no `unknown/unknown` entries in GHCR or Watchtower). OCI labels: `source`, `revision`, `version` (`sha-<short>` or the tag name), `created`, plus index annotations so GHCR shows the description. Actions used: `docker/setup-buildx-action` v4.4.1, `docker/login-action` v4.8.0, `docker/build-push-action` v7.4.0, all pinned to full SHAs. No `docker/metadata-action`: tags are computed in a shell step, because under `workflow_run` the action would read the default branch head, not the commit CI tested.
- **Entrypoint bypassed.** The image runs `nginx` directly instead of `/docker-entrypoint.sh`, whose scripts edit `/etc/nginx` and would fail on a read-only root filesystem. Our config needs none of them.
- **Watchtower is scoped** (`--scope voxel-typer`, with the scope label on the watched services and on Watchtower itself), so it can't touch another project's containers on the same host, such as the home dashboard's. Images: `nickfedor/watchtower:latest` (the maintained fork the home dashboard uses) and `tailscale/tailscale:stable`.
- **Test path: `tests/unit/deploy/headers.test.ts`, not `tests/deploy/headers.test.ts`.** `vitest.config.ts` only includes `tests/unit/**/*.test.{ts,tsx}`, so a test at the card's path would never run in `npm test` or the CI `unit` job. Moving it under `tests/unit/` also follows `README.md` §4.2 and avoids editing `vitest.config.ts`, which this card doesn't own.
- **Rollback is a `.env` value** (`VOXEL_TYPER_TAG=m2`), so the owner never edits the compose file to roll back.
