## Decisions

- **`Material` is defined in `src/types/core.ts`** and re-exported from `src/audio/types.ts` (`export type { Material }`), as briefed. Both contract paths work; a type test asserts they are the same type. `contracts.md` §1 and §12 need updating to match.
- **`src/render/atlas/painters.ts` is in the pure zone** (decision 26).
- **Mode files export a named `mode: ModeModule`** from `src/modes/<mode>/index.ts`. The contract doesn't say which export. The registry keys modes by `mode.id`, not by folder name, so `night-defense/` may hold the `defense` mode. A file without a valid `mode` export, or two files with the same id, throw at startup and name the files.
- **`resolveMode` logs a fallback once per missing mode id**, in dev only (`import.meta.env.DEV`), through `console.warn`. If `mine` itself is missing it throws, because there is nothing to fall back to. That is the state of `main` until M2-13 adds `src/modes/mine`.
- **Registry discovery is injectable:** `createModeRegistry(discovered, { dev?, warn? })`. `resolveMode` is that registry built from the real `import.meta.glob("./*/index.ts", { eager: true })`.
- **Block group files export `blocks: BlockDef[]`**, mirroring `lessons: Lesson[]`. The contract names only the lessons export.
- **`fixedStepClock(startMs, stepMs)`:** each `now()` call returns the current value and then advances by `stepMs`, so the calls give `startMs`, `startMs + stepMs`, … `epoch()` returns the latest `now()` value (`startMs` before the first call) and never advances the clock. The contract gives only the signature.
- **Emitter semantics:** subscribers run in subscription order; `emit` iterates a snapshot, so a subscription added or removed during an emit applies from the next one; unsubscribe is idempotent and removes only its own subscription (the same function subscribed twice is called twice); a throwing subscriber stops the emit and the error reaches the caller. Event names are `Map` keys, so `"__proto__"` and `"toString"` are safe.
- **`Namespace` is `keyof typeof en`, and `MessageKey` is the template type `<Namespace>.<string>`.** `MessageKey` would be `never` with no namespace, so I added `src/i18n/en/common.ts` with `appName` and `notAffiliated` (the footer text from `CLAUDE.md`). M1-12 owns that file from here.
- **Where unnamed things went:** `LayoutDef` in `src/content/layouts/types.ts`, the two lookups in `layouts/index.ts` (the file M1-11 owns); `VoxelModel` in `src/render/models/types.ts`; input types and stubs in `src/input/keyboard.ts`; `VtTestHooks` in `src/app/test-hooks.ts`, type only, with no `Window` augmentation.
- **Stub style:** stubs keep the contract's parameter names and mark them used with `void [a, b];`, because Oxlint's `no-unused-vars` rejects unused parameters and an `_` prefix would change the names workers see on hover.
- **Placeholder modules** (`engine/matcher.ts`, `engine/stars.ts`, `render/atlas/painters.ts`, `a11y/index.ts`) hold a doc comment and `export {}` with an `oxlint-disable-next-line unicorn/require-module-specifiers`. Oxlint rejects both an empty file and a bare `export {}`. The owner deletes both lines when adding real exports.
- **`VoxelModel.anims`** keeps the contract's `'idle' | 'walk' | 'hit' | 'defeat' | string` key verbatim, with an `oxlint-disable-next-line typescript/no-redundant-type-constituents`.

## Notes for downstream tasks

- **How tools load content (decision 45).** Each content folder has two entry points over one collector:
  - `index.ts` is the app's aggregator. It uses `import.meta.glob` and works only under Vite and Vitest. `@/content` and `@/modes` re-export aggregators, so they are Vite-only too.
  - `load.ts` is pure and takes already-loaded modules: `lessonsFromModules(modules)`, `blocksFromModules(modules)`, where `modules` is `{ [path]: module }`. Tools (`tools/sim.ts`, `tools/validate-*.ts`) list the folder with `node:fs`, `import()` each file and pass the record in. `isContentDataFile` from `src/content/collect.ts` filters the listing; the loaders also skip `index.ts`, `types.ts`, `load.ts`, `.d.ts` and `.test.ts` themselves. The doc comment in `src/content/lessons/load.ts` has the six-line recipe.
  - Both paths order items by file path, then by position in the file, and throw on a missing export or a duplicate `id`. Lessons are **not** sorted by `BIOME_ORDER`; sort where you need curriculum order.
  - `tests/unit/contracts/content-loaders.test.ts` loads `src/content/lessons` and `src/content/blocks` the tool way and asserts the result equals the glob aggregator's, so the two can't drift as content lands. I also ran the recipe once under `tsx`: it works, and importing `lessons/index.ts` under `tsx` fails with `glob is not a function`, as expected.
  - To add another aggregated folder (achievements, mobs), copy the `index.ts` + `load.ts` pair and call `collectExport(modules, "<export>", guard)`.
- **Tests must import `src/` by relative path, not `@/`.** Type-aware Oxlint doesn't resolve `@/` in files under `tests/`: every imported type becomes an error type and `typescript/no-redundant-type-constituents` fires on unions that use one. `tsc` and Vitest resolve `@/` fine, so only lint fails. The existing tests already use relative paths.
- **`*.test-d.ts` files are checked by `npm run typecheck`** (`tsconfig.node.json` includes `tests/**`), not by `vitest run`: Vitest's typecheck mode is off and the `include` pattern doesn't match them. A wrong `expectTypeOf` is a compile error.
- **`tests/unit/contracts/exports.test.ts` reads the stub list from the source,** so it needs no edit when you implement a stub. It does require that a remaining `not implemented: X` message sits in a function named `X`, and that top-level stubs are reachable from their folder barrel.
- **When you implement a placeholder module,** remove its `export {}` line and the disable comment above it, and add the file to its folder barrel (`engine/index.ts` doesn't re-export `matcher.ts` or `stars.ts` yet).
- **`VoxelGrid`'s constructor is real** (it allocates `sx * sy * sz` cells or adopts the given array); M1-13 implements the methods.
- **A stub's parameters are marked used with `void [...]`;** delete that line when you implement the function.
- Pure files reach types in `src/types/core.ts`, `@/i18n`, `@/save/settings` and `@/render/types` through `import type` only. See the first question below for `BIOME_ORDER`.
