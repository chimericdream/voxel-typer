# M2-07 Voxel UI kit

Status: done. Waiting on the visual review. The three screenshot baselines come from `/update-snapshots` on this PR.

## What changed

- `src/ui/theme/themes.ts`: the three themes (`day` warm, `night` cool, `contrast`), built from `BASE_PALETTE` ramps. It is the only place UI colors are defined. Each theme has 8 bevelled surfaces (outline, shadow, face and highlight) and 18 ink colors. `TEXT_PAIRS`, `UI_PAIRS` and `FOCUS_BACKDROPS` list every color pair the kit uses. Also here: the WCAG helpers (`parseColor`, `composite`, `luminance`, `contrastRatio`, `worstContrast`), `applyTheme(el, id)`, `themeFor(highContrast, tod)`, `applyTextScale(el, scale)` and `applyMotion(el, reducedMotion)`.
- `src/ui/theme/tokens.css`: tokens that don't change between themes: `--font-pixel` and `--font-body` (system fallbacks, no `@font-face`), `--text-scale` and the `--fs-*` type scale, the `--sp-1…7` spacing scale, the bevel size, the focus ring widths, the `--motion-ok` reduced-motion switch and the `[data-theme]` base styles.
- `src/ui/kit/bevel.ts`: 9-slice bevels. A 7×7 pixel-art frame (outline with notched corners, a light/dark bevel ring, then the face) is painted at 3 screen px per art pixel onto a canvas and returned as a PNG data URI. There are three kinds: `raised`, `pressed` and `inset`. Results are cached per spec. `bevelPixels` is the pure part.
- `src/ui/kit/*.tsx` + `*.module.css`: `Button`, `Panel` (and its `plate` tone), `Slot`, `Hotbar`, `ProgressBar`, `Toast`, `Dialog`, `Tabs`, `Toggle`, `Slider`, `Stars` and `KeyCap`.
- `ui-kit.html` + `src/dev/ui-kit.tsx`: developer page that shows every component in every theme. Parameters: `?theme=day|night|contrast` (default: all three, stacked), `?scale=1–2` (default 1.5, the Sprout letter size), `?motion=reduced|full` and `?dialog=1`.
- `tests/unit/ui/kit.test.tsx`: 94 tests covering contrast, the stylesheet color guard, bevels, theme application and every component.
- `tests/e2e/ui-kit.spec.ts` (outside Owns, as the brief allows): for each theme it checks for no console errors and real PNG bevels, runs axe and takes a `toHaveScreenshot`. A keyboard-only flow checks the focus ring width, the button press, the dialog trap, Escape and focus return, the tab arrows, the toggle and the slider.
- `vite.config.ts` (outside Owns, see Decisions): `ui-kit.html` is a build input only in test mode.

## Decisions

- **The kit has no strings of its own.** Every visible or spoken text (`label`, `heading`, `title`, `closeLabel`, `valueText`, `glyph`) is a prop, and callers pass `t()` output. Owns has no i18n namespace, and this keeps the kit free of copy. The only literals are symbols (`✓ ✕ ★ 999+`), which the copy lint allows.
- **Colors live only in `themes.ts`.** `applyTheme(el, id)` writes them onto an element as `--c-<token>` (kebab case), along with `--c-<surface>-outline` and the bevel images `--bevel-<surface>[-pressed]`. `tokens.css` holds the rest. One source means the contrast test checks the colors the screens actually show. Themes can be applied to any subtree (the dev page themes three sections side by side).
- **Bevels are painted at their final size** (3 px per art pixel, 9-px slices) instead of being scaled with `image-rendering`. That keeps the edges crisp in every browser. Components also set `background-color` and a solid `border-color` underneath, so they still look right when no canvas exists (happy-dom), and axe can compute contrast.
- **Theme choice:** `themeFor(highContrast, tod)`. High contrast wins. Dusk and night use the cool theme; dawn and day use the warm one.
- **Reduced motion:** `--motion-ok` (1 or 0) multiplies every duration. It is 0 under `prefers-reduced-motion`, and `data-motion="reduced"|"full"` on an ancestor overrides that (`applyMotion`; `'system'` removes the attribute). Animations then jump to their end state, so stars show full and toasts show at once. Nothing flashes: the lit-slot glow alternates every 1.8 s.
- **Dialog** uses `<dialog>` with `showModal()`, so the page behind it is inert. It adds its own Tab/Shift+Tab wrap, so focus never leaves the dialog, even for browser chrome. Escape calls `onClose` and is stopped, so the app's window-level `back` doesn't also fire. Focus returns to the opener on close.
- **Button pressed state is visual only** (`data-pressed` while Enter or Space is held, plus `:active`). The native button fires the click, and the input layer keeps key routing (M1-08).
- **Not color alone:** the selected slot gets a corner notch, a lit slot a gem and an inner ring, and the selected tab a top bar. Empty stars are hollow, the toggle knob shows ✓/✕, and disabled buttons are hatched.
- **Toast is an `<output>`** (role `status`, `aria-live="polite"`). The kit doesn't decide placement or timing.
- **Four `oxlint-disable-next-line jsx-a11y/prefer-tag-over-role` comments**, each with a reason: `ProgressBar` (block segments can't go inside a native `<progress>`), `Stars` and `Slot` (`role="img"` groups several pieces into one picture) and `Hotbar` (`role="group"`, since a `<fieldset>` needs a visible legend).
- **`vite.config.ts` changed (outside Owns, the smallest change that works):** `ui-kit.html` is added to `rolldownOptions.input` next to `atlas.html`, only when `mode === "test"`. Checked: `dist/` contains only `index.html` and `assets/`.
- **`tests/unit/ui/kit.test.tsx` starts with `/** @jsxImportSource preact */`.** Vitest otherwise compiles JSX in `tests/` against `react/jsx-dev-runtime`, and `vitest.config.ts` isn't in Owns.
- **The dev page's sample copy is literal.** Like `atlas.html`, it's a developer page, not kid-facing, and isn't in `dist/`. Hotbar icons are painted with the M1-14 atlas painters.

## Notes for downstream tasks

- **M2-10 (app shell):** import `@/ui/theme/tokens.css` once in `main.ts`. Then call `applyTheme(document.documentElement, themeFor(settings.highContrast, tod))`, `applyTextScale(root, settings.textScale)` and `applyMotion(root, settings.reducedMotion)` on startup and whenever these settings change. `applyTheme` is cheap after the first call per theme because the bevels are cached. `Dialog` handles Escape and Tab itself and stops them; `Tabs` handles Left, Right, Home and End and calls `preventDefault`, but doesn't stop them. If the window-level `attachKeyboard` also turns arrows into `left`/`right` in menus, ignore events whose `defaultPrevented` is true.
- **M2-08 (fonts):** `tokens.css` already names `"Pixelify Sans"` (first in `--font-pixel`) and `"Atkinson Hyperlegible"` (first in `--font-body`). `fonts.css` only needs `@font-face` rules with those family names. The kit test fails if `tokens.css` ever gets a `url(`, `@import` or `@font-face`. The dyslexic font toggle (Settings `font`) can override `--font-body` (and `--font-pixel` for `'dyslexic'`) on the root.
- **M2-09 (on-screen keyboard):** `KeyCap` and the `keycap` surface (`--c-keycap`, `--c-keycap-text`, `--bevel-keycap[-pressed]`) are there to reuse. Finger-zone colors aren't in the themes yet. If they carry text, add them as ink tokens with a `TEXT_PAIRS` entry.
- **M2-14 (HUD):** use `Hotbar lit={combo}` for the combo meter, `ProgressBar` for `progress01`, `Toast` for banners (`tone` matches `HudState.banner.tone`) and `Panel tone="plate"` under any text drawn over the scene.
- **Adding a color:** add it to `INK_IDS` and to every theme. If text uses it, also add a `TEXT_PAIRS` entry, or the "stylesheets use only checked colors" test fails.
- **Visual changes** to any kit stylesheet, theme color or the dev page change the three `ui-kit-*.png` baselines. Regenerate them with `/update-snapshots`.
