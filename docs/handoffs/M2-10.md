## What changed

- `src/main.ts`: boots the shell. It reads debug params, picks the save store (IndexedDB, or memory under `?nosave` / `?profile`), loads a fixture profile, makes the one shared `<canvas>` outside Preact, then wires the keyboard, the Caps Lock watcher and audio unlock and renders `App`. In non-production builds only, it lazy-loads `test-hooks` and installs `window.__vt`. `data-ready="1"` is set on `#app` when the shell is up.
- `src/app/routes.ts`: the 13 typed routes, `isRouteId`, `FOOTER_ROUTES` (splash, privacy) and the append-only `screens` table of lazy screen loaders.
- `src/app/types.ts`: `AppApi` / `ScreenProps`, the API screens get (see Notes).

- `src/app/App.tsx` + `App.module.css`: the view. - `src/app/input-router.ts`: routes `typed` keys to the mode only during live play and everything else to the current screen. An unhandled `back` goes back. Blur and hide never pause anything in menus. While paused, `back` resumes, and `confirm` resumes unless focus is on a button. Builds the full `InputCtx` (`inPlay`, `band`, `undo` while Builder runs).

- `src/app/break-reminder.ts`: counts active play time across lessons; `due(min)` and `reset()`.
- `src/app/scene-host.ts`: the one shared canvas and scene. `renderCoreFactory` dynamic-imports M2-01's `createSceneHandle` (and the block list), so three.js is a lazy chunk. `AppScene` is the interface play-host needs; `SceneCore` is compile-checked to fit it.

## Decisions

- **One scene for the app's lifetime (option A from the brief).** `createSceneHost` makes the M2-01 scene on the first play and reuses it for every later lesson. It is disposed only on `pagehide` (not a bfcache hide), because `SceneCore.dispose()` calls `forceContextLoss()`. Between lessons the canvas is hidden, play-host calls `clearDiorama()`, and with no frame subscriber, drift or tween, the loop idles.
- **Drift:** `camera.setDrift(true)` while play is `running`, and `false` on pause, break, finish and quit. Never on under `?freeze`.
- **Clocks:** `attachKeyboard` and `ModeContext.clock` always get `realClock`. The scene's loop gets `fixedStepClock(0, 16)` under `?freeze`, so only the frame loop advances it. Modes should animate from `frame(dt, t)`, not from `ctx.clock.now()`, or `?freeze` screenshots drift.
- **Pause overlay** uses the kit `Dialog`. Its focus starts on the "Keep playing" close button, so Enter resumes through the button's own click, and Escape resumes through the Dialog's `onClose`. The router's `confirm` resume applies only when no control has focus, so Enter never acts twice. A second blur or hide while paused is ignored. "Back to the map" quits the lesson without a result.
- **Break reminder:** active time is the sum of `frame` dt values during live play (pause, break and menus don't count). It carries across lessons and is checked only on `engine` `targetComplete`, so it never interrupts mid-word. Resuming from the break resets it. `breakReminderMin: 0` turns it off.
- **Autosave:** `saveProfile` catches everything. On `NewerSaveError` the profile goes read-only for the session (no retries, no overwrite) and the family sees the `newerVersion` notice. Any other failure shows `storageError` and play continues. Store `onProblem` reports (`restoredPrev`, `unreadable`, `newerVersion`, `storageError`) become kind notices through `t()`, at most one per kind on screen.
- **Audio (M2-06):** one `createAudio()` engine. `unlock()` is called from every real keydown or pointerdown (capture phase), never otherwise (M2-06 note N2). `setSpeechEnabled(settings.tts)` runs before the bus volumes on startup and on every profile/settings change. Before a profile is picked, the device settings are Miner defaults with **speech off** (N4).
- **hearAgain:** `ModeInstance` has no hook for it, so play-host emits `app:hearAgain` `{ t }` on the lesson's bus (`HEAR_AGAIN_EVENT`). The shell draws no "hear again" button. The HUD or mode that owns one should hide it when there's no local voice (M2-06).
- **Theme:** `themeFor(highContrast, "day")` for now. Day/night theme switching waits for a time-of-day source (M2-02/M3). `font: 'dyslexic'` overrides `--font-body` and `--font-pixel` on the root, per M2-07's note. `'pixel'` and `'clean'` keep the tokens.
- **The HUD bridge is a minimal store in `src/app/hud.ts`** (M2-14 owns `src/ui/hud/bridge.ts`). The Caps Lock watcher writes `capsLock` only when it changes. `reset()` between lessons keeps `capsLock`.
- **Play without a mode:** no mode folder exists yet, so `resolveMode` throws. play-host catches it, logs once (`console.error`) and shows the friendly coming-soon panel. The same happens for an unknown lesson or no active profile.
- **`__vt` is installed with `Object.defineProperty`** (frozen, non-enumerable), because `no-underscore-dangle` rejects `window.__vt`. E2E reads it with `Reflect.get`.
- **hello-voxel kept, not deleted:** it moved to `hello.html` (test build only) so its e2e coverage and baseline survive. `vite.config.ts` gained one test-mode input line (outside Owns, the smallest change).
- **Copy lint widened** to `src/app/**/*.tsx`. It was straightforward: `UI_GLOB` is now a list.

## Notes for downstream tasks

- **M2-11 (screens):** write `src/ui/screens/<Screen>.tsx` with a default export `(props: ScreenProps) => …`, then append one line to `screens` in `src/app/routes.ts`, e.g. `splash: () => import("@/ui/screens/Splash"),`. `props.app` (`AppApi` in `src/app/types.ts`) has `navigate(route, { replace })`, `back()`, `canGoBack()`, `profile()`, `setProfile()`, `saveProfile()` (never rejects), `store`, `lessons`, `lesson(id)`, `lastResult()`, `recording()` (the `?record` keystroke log, for the Results download), `audio` (call `audio.unlock()` on Splash's "press any key"; the shell also unlocks on every gesture), `whenReady(promise)` (so `__vt.ready()` waits for your assets) and `onInput(handler)`. Tab and Enter keep browser defaults (focus moves, buttons click), so don't also act on `next` or `confirm` when a button has focus. Go to a lesson with `navigate({ id: "play", lesson })`. The shell then routes to `{ id: "results", lesson }` with `replace`, after the profile is saved. The footer disclaimer is drawn by the shell on splash and privacy, so screens don't add it.
