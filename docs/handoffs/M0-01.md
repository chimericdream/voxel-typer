## Decisions

- **Purity rules: what Oxlint does natively and what is in `tools/check-boundaries.ts`.** I probed Oxlint 1.93.0 with violation fixtures before deciding:

  | Rule                                                                                                                                                                                                                                              | Where                                                         |
  | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
  | `three`, `three/*`, `preact`, `preact/*`, `@preact/*`, `idb`, `@/ui/*`, `@/audio/*`, `@/app/*`, `@/render/*` except `@/render/mesher/*` and `@/render/atlas/recipes`. This covers value imports, `import type`, re-exports and dynamic `import()` | Oxlint `no-restricted-imports` (patterns; `!` negation works) |
  | `window`, `document`, `navigator`, `localStorage`, `indexedDB` as bare names                                                                                                                                                                      | Oxlint `no-restricted-globals`                                |
  | `Date.now`, `Math.random`, `performance.now`, including `const { now } = Date` and `Math["random"]`                                                                                                                                               | Oxlint `no-restricted-properties`                             |
  | **Relative** imports that resolve into a forbidden folder (`../ui/x` from `src/engine/`). Oxlint matches the import string, not the resolved path                                                                                                 | `check-boundaries` `relative-import`                          |
  | Banned globals reached through a global object (`globalThis.document`, `self["navigator"]`, `window.localStorage`)                                                                                                                                | `check-boundaries` `global-object-access`                     |
  | `globalThis.performance.now()`, `self.Math.random()` and the like                                                                                                                                                                                 | `check-boundaries` `global-object-access`                     |
  | `new Date()` / `Date()` with no arguments (a clock read, like `Date.now`; `new Date(ms)` is allowed)                                                                                                                                              | `check-boundaries` `wall-clock`                               |

- **Pure zones may import `@/render/mesher/**` and `@/render/atlas/recipes` from any pure zone, not only from each other.** The contracts need this: `BlockDef.faces` in `src/content/blocks/types.ts` uses `TextureRecipe`, and `Profile.island` in `src/save/schema.ts` uses `VoxelGrid`.
- **Additions beyond the card's ban list:** `idb` (wraps IndexedDB) and zero-argument `new Date()`/`Date()`. Both are the same thing as bans the card already has.
- **Type-aware linting is ON** (`options.typeAware: true`, via `oxlint-tsgolint@7.0.2006`). Oxlint's schema marks `typeCheck` as experimental but does not mark `typeAware` that way. It runs on Windows and in the Linux container, and it found real problems while I worked: unchecked `JSON.parse(...) as T` casts and unnecessary assertions. It adds about 0.5 s (lint takes 1.5 s instead of 1.0 s). The cost: `typescript/no-unsafe-type-assertion` (in `suspicious`) is strict, so parse JSON into `unknown` and narrow it with a type guard instead of casting.
- **The boundary script uses `oxc-parser`, not the TypeScript compiler API.** The current stable TypeScript is 7.0.2 (the native Go compiler). Its npm package exposes only `typescript/unstable/*` and no stable JS compiler API. `oxc-parser` is part of the Oxc stack, gives a typed ESTree AST with a `Visitor`, and is fast. Using TypeScript 7's unstable API, or adding a second TypeScript 6 install just for tools, both looked worse.
- **Build tooling is in `devDependencies`** (`vite`, `typescript`, `@preact/preset-vite`, `@types/three`), although the card lists them with the runtime packages. Runtime `dependencies` are only `preact`, `@preact/signals`, `three` and `idb`, so M0-03's `npm audit --omit=dev` checks what actually ships.
- **Oxfmt ignores `PLAN.md` and `docs/impl/**`.** Oxfmt also formats Markdown and would rewrite those orchestrator-owned files, which are outside this card. The orchestrator can run `npx oxfmt PLAN.md docs/impl` in its own commit and remove the two ignore entries.
- **The e2e build goes to `dist-test/`** (`vite build --mode test`, also available as `npm run build:test`). It stays separate from the production `dist/` that `npm run size` measures. `E2E_SKIP_BUILD=1` makes Playwright serve an existing `dist-test/` without rebuilding.
- **esbuild's postinstall script is denied** (`"allowScripts": { "esbuild": false }`, written by `npm install-scripts deny esbuild`). npm 11 warns about unapproved install scripts. esbuild (pulled in by tsx and vite) gets its binary from platform optional dependencies, so the postinstall isn't needed. tsx, vite and the Docker run all work without it.
- `import/no-unassigned-import` (in `suspicious`) allows `**/*.css` so Vite CSS imports work. Other side-effect imports still error.
- React plugin settings: `react-in-jsx-scope`, `jsx-filename-extension` and `no-unknown-property` are off (Preact uses the automatic JSX runtime and DOM attribute names). `settings.react.version` is `19.0`. I checked that a `.tsx` Preact component lints and typechecks, and that `jsx-a11y` rules fire (`alt-text`).
- Coverage thresholds are switched off at first. M1-GATE turns them on by setting `COVERAGE_THRESHOLDS=1` in CI, or by flipping `enforceThresholds` in `vitest.config.ts`.
- Screenshot baselines go to `tests/e2e/__screenshots__/<spec file>/<name>.png`, with no OS or browser suffix, because baselines are only ever made on Linux.
