# M3-13 Progression simulation study

Status: done

A learner model with a power-law learning curve per key now plays the whole shipped curriculum
(Meadow, Birch, Shore and Frosty, 55 lessons) through the game's own code. The report is in
`docs/sim.md` under "Progression study". The plausibility targets hold. A median average Miner
finishes the Meadow in **14** sessions (target 8–20) and biomes 1–4 in **68** (target 40–90).

Three things look discouraging for young or slow learners: a failed mastery check sends the child
back to lesson 01, remedial camps take up a third of a slow child's sessions, and slow Sprouts see a
lot of 1★. Concrete proposals are below. None is applied.

## Proposals (for the orchestrator's fix cards; nothing applied)

Lesson lengths don't need to change: every band's median is in range, and fast learners are within
4 sessions of the fastest possible path (54).

1. **Go back to the mastery check, not to lesson 01** (`src/app/recommend.ts`,
   `nextCurriculumLesson`). When nothing fresh is left and the current biome's mastery lesson has
   been played with fewer than 2 stars, recommend the mastery lesson. A gentler version
   alternates: one replay of the fewest-star lesson, then the mastery lesson. Today the
   fewest-stars rule replays the biome from lesson 01, and each replay has to get past 1★ before
   the next comes up.
   - Measured with `--policy mastery-first`. Learners with a stuck run: slow Sprouts 95 % → 65 %,
     average Sprouts 73 % → 5 %, slow Miners 75 % → 15 %, slow Builders 33 % → 3 %.
   - Median longest run without an unlock: 32 → 5 (slow Sprouts), 13 → 2 (average Sprouts).
   - Slow Sprouts finish biomes 1–4 in 87 sessions instead of 131. Fast and average learners
     don't change.
   - The child-safety-and-fun case: the trace of `sprout:slow:0` has 31 sessions of old Meadow
     lessons between a 1★ mastery play and the 3★ one.
2. **Make the remedial trigger relative** (`src/engine/remedial.ts`).
   - Slow learners get a camp in every free slot: 31–32 % of their sessions, the rate limit's
     maximum. For average learners it is 17–27 %.
   - One camp lowers the true slip chance on its keys by only 0.2–0.4 points, and only 31–49 % of
     its keys are among the learner's three truly weakest.
   - Passing every camp by leaves the two weakest keys 0–2 points worse at the end, and biomes 1–4
     take about 14 fewer sessions.
   - Proposal: a key is weak only when its weight is ≥ `REMEDIAL_MIN_WEIGHT` (4) **and** ≥ 1.5 ×
     the median weight of the allowed keys, so a child who is new to every key isn't flagged all
     the time. Also raise `REMEDIAL_EVERY` from 3 to 4. **Not simulated**, because these are
     `const` primitives the tool can't patch. Rerun `--study` after the change.
3. **Sprout's second star at 80 %** (`BAND_STAR_RULES.sprout.secondFloor` 0.85 → 0.80). This is
   an **owner decision**, because it changes decision 80. Slow Sprouts get 1★ on 59 % of plays,
   with a median longest run of 10 in a row (the worst: 20). Average Sprouts: 44 % and 6.
   - Checked with a throwaway script (not committed) that patched the rule: slow Sprouts 1★ 59 % →
     41 %, longest 1★ run 10 → 5; average Sprouts 44 % → 22 %, 6 → 3.
   - The mastery gate doesn't move: mastery's bar stays at 85 % (target 0.90 − 0.05).
   - Together with proposal 1, slow Sprouts are at 52 % 1★ with a longest run of 6.

## Decisions

- A biome counts as finished when its mastery lesson earns 2 stars, which opens the next island.
  Camps count as sessions.
- Defense nights are played as Mine sessions of the same words, with Mine's stars. The director
  and the visitor part of `nightStars` aren't modelled. Defense nights never gate a biome (any
  play opens the next lesson), so finish times don't depend on this; their star counts are a
  little optimistic.
- The learner's numbers are assumptions from rough grade-level typing figures. They were set before
  the first run and not tuned to the targets.
- Learners skip placement and start at the Meadow. The placement sim's `playPlacement` doesn't
  return the per-rung scores that `applyPlacement` needs.
- `focusKeys` is copied into the tool because `mine.ts` loads Vite-only modules. A test checks the
  copy against the real one.

## Notes for downstream tasks

- **A possible bug for the orchestrator to triage** (`src/app/recommend.ts`, not fixed here).
  `remember()` caches handed-out remedials by id, and the id is a hash of the keys and the
  session index only. Two profiles on one device, in one page load, with the same weak keys at
  the same session counter, get the first profile's lesson object. That object has the other
  profile's anchor biome, review keys and pools, so it can ask for keys this child hasn't learned.
  Fix: put the profile id (or the anchor id) into `remedialId`'s hash. The sim calls
  `resetRemedials()` for each learner to stay clear of it.
- The tool is the place to measure any fix to the proposals above:
  `npm run tool -- sim-progression --study --runs 40 --seed 1`. `--trace` shows one child's
  sessions.
- Biomes after Frosty have no lessons yet. The study picks them up automatically when their
  lesson files land.
