## Decisions

- **Getting in.** Settings → Grown-ups (already gated) has "See {name}'s progress". It hands the pass
  on with `handGrownUpPass()`, and the dashboard takes it once with `takeGrownUpPass()`. Any other
  way in, such as `?screen=parent` or a later visit, asks the gate (`parentDashboard`). Back returns
  to Settings, which asks again for Grown-ups, as M3-08 decided (one gate per Settings visit). This
  is still the speed bump of decision 105.
- **Tested-out lessons.** Curriculum rows go through `isTestedOut()`. A tested-out lesson shows
  "Tested out" in place of speed and accuracy, and each biome counts them ("2 lessons tested out").
  Its one star still counts toward the biome's stars, as on the map. Trends read `history` only,
  which never holds tested-out records.
- **Remedial practice.** Sessions with a `remedial-` lesson id count in minutes, trends and the CSV,
  and are labelled "Practice". Curriculum progress reads `app.lessons` and drops any `remedial-` id.
  Both checks use M3-06's `isRemedialId` from `src/engine/remedial.ts` (main is merged in).
- **Session labels.** A curriculum lesson shows its title. Otherwise: mode `placement` → "Placement
  test", mode `daily` → "Daily challenge", everything else (free practice, remedial) → "Practice".
- **Numbers.** Minutes have 1 decimal place, WPM is whole, and accuracy is a whole percent. The page
  and the CSV use the same rounding helpers. Sessions under 1 s of active time (no rates,
  contracts §3.5) stay out of the speed and accuracy trends but count their minutes.
- **Weak keys** use `KeyStat.recentErrRate` (the EMA, so "recent mistakes"). A key's plain and Shift
  characters are merged and weighted by presses. A key needs 20 presses before it gets a color, and
  a pair needs 10 tries.
- **"Keys to practice most" lists only keys that stand out:** at least 2 percentage points above
  the median key (`STAND_OUT`). When every key is alike, it says "No key stands out. Mistakes are
  spread evenly across the keys." The first baselines showed Q, W, E, R, T at 3% each listed as
  "practice most", which implied a ranking that wasn't there. Letter pairs use the same rule.
- **The heat-map caption** points at the legend ("The steps above show what each color means").
  An earlier "Lighter keys are going well" was wrong on the dark themes, where the steps run the
  other way. Keys go in 5 bins: under 2%, 2–5%, 5–10%, 10–20%, 20% or more. Each key
  prints its percent, so color is never the only cue.
- **Letter pairs** show only for the Builder band, as the card says.
- **Colors.** One hue (blue) for every chart, checked with the dataviz validator. Line and bar
  colors pass 3:1 on each theme's panel face: day `#1c5cab` on `#e6d8ac`, night `#86b6ef` on
  `#444852`, contrast `#5fcdd4` on `#000`. The heat steps go light to dark on day, dark to light on
  the dark themes. The lowest step may fade into the panel, because it means "hardly any mistakes".
  Every key keeps an edge, and the ink is black or white, whichever reads better. Under
  `forced-colors` the marks use `CanvasText`.
- **Chart text** is drawn at the box's measured pixel width (viewBox = px), so labels use the real
  type size at each text scale. The heat map's key labels scale with key size instead. Its table
  and the "keys to practice" list carry the numbers at full text size.
- **CSV.** Columns: Player, Date (local `YYYY-MM-DD`), Time (`HH:MM`), Activity, Minutes, Speed
  (WPM), Accuracy (%). There is no profile id, age band or avatar. Any text cell that starts with
  `= + - @`, a tab or a CR gets a leading `'`. Numbers are never escaped. The file is UTF-8 with a
  BOM and CRLF line ends. Its name is `voxel-typer-sessions-<nickname slug>-<date>.csv`, and the
  slug keeps only `a–z0–9-`.
- **No growth claims.** Captions only say what a chart measures and "Higher is better".
- **The fixture has no `bigramStats` and gives every key 3%**, so on `veteran-builder` the pair panel
  shows its empty state and the heat map is one step. A unit test covers the other bins with edited
  key stats. I didn't change the shared fixture, because other baselines use it.
