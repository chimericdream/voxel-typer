## Decisions

- **Double-handled keys:** the router never sees `defaultPrevented`, so `useScreenInput` drops a control whose keydown a component already handled. A `document` keydown listener runs before the router's `window` listener and records the flag. Screens never act on `confirm`/`next` while a control has focus, because the browser's click or focus move is the action.
- **Key repeat:** the router never gets repeats (`normalizeKeyEvent` drops them). Kit `Button`/`Dialog` ignore held Enter. The custom player buttons and the name field `preventDefault` a repeated Enter. Saves and loads use a latch, so a double submit makes one player.
- **Results arm after 700 ms:** the screen comes up while a child may still be typing, and Next has focus, so a stray Space would skip the stars. Presses in the first 700 ms do nothing.
- **Star sounds** land as each star fills (300 ms, then every 350 ms, matching the kit's stagger). Under reduced motion (profile setting, or the system's when "system"), the stars and slots appear at once and one `star` plays.
- **Personal best:** this run beat every earlier run of the lesson in `history` on net WPM or on accuracy. The first play is never a "best".
- **Goal line** comes from the lesson's `newKeys` (`goalLine`): "Find the F and J bumps!" for F+J, "Find the {key1} and {key2} keys!", "Find the {key} key!", "Find the new keys!" for 3+, and "You know all these keys. Let's type some words!" for review lessons. No Lesson change needed.
- **No "hear again" control** on these screens. The card doesn't ask for one, so there's nothing to hide when no local voice exists.
- **The map is M3-04.** Until then, the map route's coming-soon panel offers "Play: <title>": the first unplayed lesson in an unlocked biome, otherwise the last one. Without it, the slice had no way from a new player to lesson 1 (M2-15 flow 1, and the M2-GATE playtest).
- **Read-only profiles** (`NewerSaveError`): the store's `listProfiles` skips a profile a newer build wrote. If it is the active profile, Profiles still lists it from memory, notes "Saved by a newer game. You can play, but new stars will not be saved.", and lets the child play. A newer-version profile that was never loaded is counted in a note ("One player was saved by a newer version of the game. Ask a grown-up to update the game. Your progress is safe."), so it doesn't vanish without a word.
- **Refusal copy** is the same for every blocked name ("Let's pick a different name. Try another one!"). It never echoes the name or says why. Odd chars can't be typed, so they never need a message.
- **Skin colors** are 6 original tones, light to deep (`tone-1`…`tone-6`), saved in `avatar.skin`. Their accessible names are "Skin color 3 of 6", not food or ranking words. An unknown id (the fixtures use `moss`, `slate`…) draws the middle tone.
- **Single letters use `--font-body`** (M2-08): the intro's KeyCaps override the kit's pixel font in the screen's CSS.
- **Text on slots:** `text`/`slot` isn't a checked contrast pair, so band cards and the name field use the panel face behind text.
