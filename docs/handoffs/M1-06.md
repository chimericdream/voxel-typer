## Decisions

- **Rule priority.** When rules conflict, the earlier one wins: (1) the allowed set, which is
  never relaxed; (2) the blocklist for random letters; (3) the `letters` run limit; (4) the
  comfort cap. A lower rule only gives way when the higher one leaves no candidate.
- **Bottom half (comfort cap).** Take the distinct non-space allowed keys and sort them by weight.
  A key is comfortable when its weight is ≤ the weight at rank `ceil(n/2)`. Ties are never split,
  so with equal weights every key is comfortable. Missing, non-finite or non-positive weights
  count as 1. Space is left out of both sides of the share. The share is measured on the text
  before capitalization.
- **How the cap is enforced.** `letters` and `syllables` use a greedy rule per char: when one more
  non-comfortable char would push the running share under 50%, the pick is limited to
  comfortable keys. A syllable may give up its consonant–vowel slot to do this. Word-like kinds
  use rejection sampling as §5 asks: up to 200 weighted draws per target, accepting the first
  item that keeps the running share ≥ 50%. After that the cap relaxes to the most comfortable
  item (the first one in pool order on a tie). So the cap holds whenever at least one candidate
  item is ≥ 50% comfortable.
- **The "< 4 keys" exception.** The card expects the cap to fail sometimes with fewer than 4
  keys. With this design it holds for any key count in `letters` and `syllables`, except for one
  edge: the blocklist or the run rule can force a single non-comfortable char. Example: allowed
  `{a, s}` with `s` the only comfortable key, the tail is `as`, and `ass` is blocked. That miss
  is at most about one char before the greedy rule recovers. The 500-case property uses ≥ 4 keys,
  as the card says.
- **Blocklist for random letters (child safety).** `BLOCKED_RUNS` is a short, plain-text list of
  offensive or rude letter runs, such as `ass`, `fuk` and `sex`. Syllables that contain one are
  redrawn, up to 20 tries, then replaced by a single comfortable char. The `letters` stream never
  ends in one, so letters typed back to back can't spell one either. Pool items are not checked:
  they are curated, and the word-list pipeline validates them. The project's word-list blocklist
  doesn't exist yet. When it lands, the two lists could be merged.
- **Syllable shapes.** Vowels are `aeiou`. Every other allowed key counts as a consonant,
  including `;` and `y`. Length-2 shapes are CV, VC and VV. Length-3 shapes are CVC (weighted
  double), VCV and CVV. With no vowels every slot is a consonant, and with no consonants every
  slot is a vowel. `minLen`/`maxLen` narrow the 2–3 range where they overlap it and are ignored
  otherwise.
- **Pool candidates.** An item is a candidate when it is typeable, non-empty, has no leading,
  trailing or double spaces, and fits `minLen`/`maxLen` in code points. Duplicates across pools
  are dropped. If nothing qualifies, the generator falls back to syllables (§5). So a lesson whose
  items all fall outside the length bounds also gets syllables.
- **Item weighting and repeats.** An item's weight is the sum of its non-space chars' weights,
  picked in O(log n) with exactly one `next()` per draw. Picking the same item twice in a row
  counts as a rejection when there is more than one candidate.
- **Length.** `{chars}` counts the spaces between word-like targets: the generator stops at the
  first target where text plus separating spaces reaches the budget. `{seconds, estWpm}` becomes
  `{chars: ceil(...)}`. Negative or non-finite numbers throw a `RangeError`. Budgets are clamped
  to 20,000 chars or 5,000 targets so a bad value can't hang the game. If allowed has no
  non-space key, the result is `[]`.
- **`capitalize`.** `'first'` upper-cases the first char of every target. `'mixed'` does it with
  chance 0.5 per target. Either way, it happens only when the upper-case char is in `allowed`
  (rule 1), so with today's lower-case allowed sets it does nothing.
- **Targets.** Ids are `g0`, `g1`, …. `trailingSpace` is `false` for `letters` and `true` for
  everything else. The session ignores it on the last target.
- **`typeable`.** It works per code point and always accepts a space, matching
  "allowed ∪ {' '}". `typeable('')` is `true` (vacuous); the generator filters out empty items
  itself.
- **RNG streams.** Fixed fork labels per consumer: `letters`, `syllables`, `items`, `capitalize`.
  The word-to-syllable fallback uses `syllables`.

## Notes for downstream tasks

- **M1-07 (simulator):** the constants are in `GENERATOR_CONSTANTS`, which is read-only (`as
  const`). If tuning needs them to be parameters, raise that. `comfortableKeys(allowed, weights)`
  and `lengthBudget(length)` are exported so the harness can check shares and budgets the same
  way the generator does.
- **M3-01 (curriculum validator)** and the word-list pipeline: an item that fails `minLen`/
  `maxLen` is not a candidate, and a lesson with no candidates silently gets syllables. The
  validator should check typeable items within the length bounds, not just typeable items.
- **Word-list blocklist owner:** `containsBlockedRun` and `BLOCKED_RUNS` in `generator.ts` guard
  random letters only. Consider sharing one list in a pure module when the pipeline's blocklist
  lands.
- Changing any generation step changes the inline snapshot in the test and every fixture that
  M1-07 records. That is expected; update them together.
