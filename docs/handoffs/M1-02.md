## Decisions

- Number seeds are reduced with `>>> 0`, so `createRng(-1).seed === 4294967295` and fractions
  are dropped. `seed` is always a uint32.
- `fork(label)` is `createRng(hashString(`${seed}:${label}`))`, where `seed` is the parent's
  numeric uint32 seed. A string-seeded parent therefore forks from its hash, not from the
  original string. This follows the card's formula.
- `fork` does not depend on how much of the parent stream has been used. Calling it before or
  after any number of `next()` calls gives the same child.
- `int` uses `floor(next() * span)`. `next()` has 32 bits of resolution, so `int` is uniform for
  small spans and only approximately uniform for spans close to 2^32 or larger. It throws a
  `RangeError` if a bound is not a safe integer or if `min > max`.
- `weightedPick` throws a `RangeError` if the array lengths differ, if a weight is negative, NaN
  or infinite, or if no weight is positive. Zero-weight items are skipped.
- To satisfy `noUncheckedIndexedAccess` without casts, an `at()` guard reads each element. As a
  result, `pick`, `weightedPick` and `shuffle` throw if an array element is literally `undefined`.
  No caller in the game passes arrays like that.
- No warm-up discard after seeding. Seeding through splitmix32 makes it unnecessary, and the golden
  values depend on this choice.

## Notes for downstream tasks

- **M1-06 (generator) and M1-14 (palettes/atlas):** derive substreams with `rng.fork('<label>')`
  instead of sharing one stream between independent consumers. A fixed label gives a stable child
  stream no matter how many draws came before it, so adding a draw in one consumer doesn't shift
  another consumer's output. Choose short, fixed labels (for example `'words'`, `'letters'`,
  `'palette:<rampId>'`) and never build a label from data that changes between runs.
- The sequence for every seed is frozen by the golden test. Changing a constant or a step in
  `rng.ts` changes every daily challenge and every fixture.
- `dailySeed({y, m, d})` returns `"daily-YYYY-MM-DD"` with zero padding. Pass it straight to
  `createRng`. The caller supplies the local date.
- `pick` and `int` each use exactly one `next()` call. `shuffle` uses `length - 1` calls, and
  `weightedPick` uses one. Fixture authors can rely on these counts.
