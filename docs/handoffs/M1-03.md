## Decisions

Each of these fills a gap the contract leaves open. None changes a contract type.

- **Trailing space is required only while another target follows.** The last target of the queue completes on its last char. The session re-checks when targets are added or removed: a target added behind the current one gives it a space; removing the next target drops the space, and completes the current target if its text was already typed (`removeTarget` then returns that `targetComplete`). Reason: "before the next target" in §3.2, and a kid should not have to press space after the last word of a lesson.
- **The trailing space is a position of its target.** `correct`/`wrong` for it have `index === text.length`, and while the space is required `TargetView.marks` has `text.length + 1` entries (`typed` can equal `text.length` with `complete: false`). `TargetView.text` stays the bare text. Reason: §3.3 calls the space a real char, and under `backspace` a wrong key at the space needs a mark to show.
- **Marks.** A right key marks `ok`, or `fixed` if that position ever took a wrong key (all policies). Under `stay` the position under the cursor shows `wrong` after a wrong key until the right key lands.
- **`targetComplete` fields.** `errors` = positions that took at least one wrong key (once per position, per §3.2 "Error counted once per position"). `accuracy` = correct keystrokes / all keystrokes on that target. `durationMs` = first key on the target to completion, minus paused time.
- **Event order.** `targetLocked` → `correct` → `streak` → `targetComplete` → `sessionEnd`; for a wrong key `wrong` → `streakBroken` → (`targetComplete` under `skip`). A completed lockOn target releases the lock without a `targetUnlocked` event; that event is only for Backspace-unlock and `removeTarget`.
- **`backspace` policy, target typed to the end but still wrong:** further keys are `wrong` with `index = text length` and `expected: null`. They count as keystrokes and errors. The cursor does not move.
- **A lockOn key that starts no target** is `wrong` with `targetId: null` (contract). The `sequential` case is ruling Q1 below.
- **lockOn priority:** a target without `priority` sorts after every target that has one (treated as `+Infinity`).
- **Latency** is the time since the previous key that reached the same target, including an effective Backspace. An ignored Backspace does not count. It is `null` when there is no such key: the target's first key, the first key after `resumed`, the first key after a re-lock.
- **The clock starts at the first key fed while unpaused** (`startedAtT`). `createSession` takes no time, so nothing earlier can count. Timestamps that go backwards are clamped and never shorten active time.
- **`time` sessions:** the feed at or after the deadline is not typed; it returns only `sessionEnd`. `activeMs` and `view().elapsedMs` are capped at the limit, also when the mode calls `end` late.
- **`targets` sessions end only on a completion**, never because the last open target was removed. A mode that removes targets calls `end` itself.
- **Leniency.** Keys fed while paused, and keys that are not one char or Backspace, return `[]` and are not counted (they are still logged). After the end, `end`/`pause`/`resume`/`removeTarget`/`addTargets` are no-ops and are not logged; only `feed` throws. `removeTarget` with an unknown id returns `[]`. `pause` while paused and `resume` while running return `[]`.
- **`addTargets` throws** on an empty `text` or an id that a not-removed target already has (nothing is added in that case). An id can be reused after its target is removed.
- **`uncorrected`** counts `wrong` marks on targets still in the session at the end, under `skip` only. Removed targets don't count ("no errors counted").
- **Live values** use `(correct in window / 5) / (window minutes)` with window = `min(10 s, elapsed)`; `liveAccuracy` is 1 when the window holds no keystrokes (matches the summary's zero-keystroke rule). `view()` takes no time, so they are as of the last call that carried a `t`.
- **Interim stats** (until M1-04): `consistency` is 1 when the mean latency is 0. Per-key and bigram counting: one attempt per keystroke aimed at an expected char, one error per wrong one, except a repeated wrong key at the same `stay` position (not counted per key). Bigrams pair an expected char with the expected char before it in the same target, trailing space included; they don't cross targets.

### Orchestrator rulings (review of PR #103)

These were my four questions. The orchestrator ruled on them in the review, and the wording is now in `contracts.md`.

- **Q1, approved: in `sequential`, a key fed when no target remains is ignored.** No event, not a keystroke, no streak break (§3.3, §3.5). Such a key does not start the session clock. A running `time` session still ends on it once the deadline has passed. `lockOn` misses are unchanged.
- **Q2, approved: under `lockOn` with `stay`, Backspace while locked unlocks and resets the target** (§3.2). It emits `targetUnlocked`, the typed progress goes back to 0 and every mark to `pending`. Keystrokes already counted stay counted, in the summary and in the target's later `accuracy`; positions that took a wrong key stay in its `errors` and show `fixed` when retyped. Under `skip` and `backspace` nothing changed: Backspace unlocks at 0 typed chars.
- **Q3, kept as built: `TargetView.marks` has `text.length + 1` entries while a trailing space is required** (§3.4).
- **Q4, kept: `consistency` uses the population standard deviation** (§3.5).

### Review fix

- **A pause in progress no longer counts toward a target's `durationMs`.** `resume` is what credits a pause to the active target, so a target that settled during the pause (`removeTarget` dropping its trailing space) got the whole pause as duration. `settleTarget` now takes the pending pause as a fourth argument and the session passes it. Nothing is stored, so a later `resume` cannot subtract it twice. `activeMs`, `elapsedMs` and `end` during a pause were already right; tests now pin them.

## Notes for downstream tasks

- **M1-04: the accumulator plug-in.** `session.ts` exports three types (also through the `@/engine` barrel):

  ```ts
  interface KeystrokeFact {
    t: Ms;
    correct: boolean;
    expected: string | null; // null: no target took the key, or the target was already full
    got: string; // for a correct key, the expected char
    previous: string | null; // expected char before this one in the same target (bigrams)
    latencyMs: Ms | null; // as on the `correct` event; always null for a wrong key
    repeat: boolean; // stay only: another wrong key at a position that already took one
    streak: number; // streak after this keystroke
  }
  interface SummaryContext {
    config: SessionConfig;
    startedAtT: Ms;
    activeMs: Ms;
    uncorrected: number;
  }
  interface SummaryAccumulator {
    keystroke(fact: KeystrokeFact): void; // once per counted keystroke, in order
    targetCompleted(): void;
    summarize(context: SummaryContext): SessionSummary;
  }
  ```

  The session calls `keystroke` for every non-Backspace key fed while unpaused, `targetCompleted` per `targetComplete`, and `summarize` once at the end. It does no stats math itself. To plug in: make `createAccumulator()` in `stats.ts` return a `SummaryAccumulator` (a structural match is enough; `import type` from `./session` is allowed in the pure zone), then in `session.ts` change the last line `const newAccumulator = createLocalAccumulator` to point at it and delete `createLocalAccumulator`, `bump` and `consistencyOf`. No signature changes. The card's `summarize(acc, activeMs)` can sit underneath the method. If M1-04 picks different counting rules, the six fixture summaries and the "summary" tests in `session.lifecycle.test.ts` need the same change.

- **M1-07: `replaySession(snapshot) → { session, events }`** is exported beyond the contract. `restoreSession` drops the events, so `replay()` can't get the summary from it; take it from the `sessionEnd` event of `replaySession`. A log that never ended has no `sessionEnd`; call `session.end(t)`.
- **Fixture format** (`tests/fixtures/logs/*.json`): `{ name, why: string[], snapshot: SessionSnapshot, expected: { summary: SessionSummary } }`. Times are chosen so the rates are exact doubles (`minutes` is a power of two).
- **Modes: completed targets stay in `view().targets`** until `removeTarget` (contract: "all not-yet-removed targets"). Long lockOn sessions should remove popped mobs.
- **Modes: keep at least two targets queued in `sequential`** if words should be separated by spaces. A target only requires its space while a next target exists, so adding targets one at a time after each completion yields no spaces.
- **Orchestrator: `src/engine/types.ts` and `src/engine/stats.ts` doc comments** still carry the old wording for the four rulings (Backspace under `stay`, `keystrokes`, `marks`). They are orchestrator-owned, so I left them; `contracts.md` is updated.
- **Input (M1-08):** the engine accepts Backspace or one char by code point and ignores everything else. `shift` and `code` are ignored. With `caseSensitive: false` the match is `got.toLowerCase() === expected`.
- The matcher exports are public through the barrel but are not contract; only the session should need them.
