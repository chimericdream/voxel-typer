## Decisions

- **Diagonal flip.** The default split is the ao1–ao2 diagonal (corner numbering ao0 = (0,0), ao1 = (1,0), ao2 = (0,1), ao3 = (1,1) in face u/v). It flips to ao0–ao3 when `ao0 + ao3 > ao1 + ao2`, with AO values as occlusion levels (higher = darker), so the split always runs through the darker pair. This is the 0fps rule. Ties keep the default.
- **Transparent blocks never occlude AO**, and their own faces receive AO like opaque ones.
- **Positions are grid-absolute** (block `(x, y, z)` spans `[x, x+1]³`), so all chunk meshes of one grid share one transform.
- **Chunk bounds are clamped to the grid**: a chunk partly or wholly outside the grid meshes only the cells inside it.
- **Side-face `v` runs +y**, so side textures stand upright. Top faces use u = +x, v = −z; bottom faces use u = +x, v = +z.
- **`set` out of bounds is a no-op** (the contract only specifies `get`). It mirrors `get`.
- **Benchmark bound on CI is 200 ms** instead of skipping the test, so it still runs everywhere.

## Notes for downstream tasks

- **M2-01 (render core):** `colors` is RGB (3 floats per vertex, all equal) holding the AO brightness. Use `vertexColors: true` and multiply it with the texture. Indices are `Uint32Array`, and three.js accepts them as is. Every quad is 4 vertices and 6 indices, in order, so per-quad data can be found by `q * 4`.
- Triangles wind counter-clockwise seen from outside (three.js front faces, so `FrontSide` works). Transparent blocks (water, glass, leaves) are in the same mesh as opaque ones. If M2-01 needs separate opaque and transparent draw calls for sorting, it can call `meshChunk` with an `AtlasLookup` wrapper per pass, or ask for a split output (that would be a contract change).
- `meshChunk` calls `atlas.transparent(id)` once per block id per call (cached in a 64 K table), and `atlas.uv` once per emitted face.
- Meshing does not mutate the grid and is safe to run in a Worker later.
- `fromJSON` throws `RangeError` on malformed input. The save loader (M1-09) should catch it.
