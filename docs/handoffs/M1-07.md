## Decisions

- **`replay` ends an unfinished log at its last timestamp** (`add` entries carry no time). The
  optional `endAt` overrides this. `endedInLog` tells the caller which case happened.
- **One sim run = one learner playing `--sessions` sessions in a row** (default 5). `--runs` is
  the number of independent learners. Between sessions the tool folds key and bigram stats with
  the real fold functions, and the next session's content comes from `keyWeights`.
- **Corrections under `stay`: no Backspace.** The typist waits the 150–400 ms notice delay and
  types the right key. Under `stay`, Backspace is ignored in `sequential` and resets a locked
  `lockOn` target, so a human wouldn't press it. Under `backspace` the typist presses notice →
  Backspace → retype, as the card says.
- **Learning model:** `errorProbability = errorRate × mult × 1 / (1 + learnRate · attempts / 100)`,
  capped at 0.9. `jitter` is the σ of the log latency.
- **The adaptive engine ranks letters only.** The sim passes `allowed` without space, so space is
  never a weak key. The generator adds space by itself.
- **`adhoc` lesson:** Meadow's ten keys, no focus keys, `stay`, `practice` mode, accuracy goal 0.9,
  150 chars per session, `syllables` by default (`--kind letters` for single-key drills). No lesson
  files or word pools exist yet, so `--lesson <id>` reports "no lesson … (none yet)" and exits 2.
- **`lessonFromData` resolves a lesson's allowed set itself**: the cumulative `newKeys` in
  `BIOME_ORDER`, with Sparkstone only for Sparkstone lessons. `allowedKeysFor` is still a stub. It
  uses the contract §6 defaults for policy, band scale and case. `defense`/`boss` modes use
  `lockOn`. Timed lessons use the typist's wpm as `estWpm` until a baseline exists.
- **Stars:** "completed" means the session ended by its own rule (last target or deadline).
- **Tuned constants:** `errorWeight` 10, `latencyWeight` 1. The reasoning is in docs/sim.md:
  raising the error weight relative to the latency weight is the only lever that changes the
  ranking, the gain levels off at 10, and latency keeps enough weight to flag keys that are slow
  but not wrong.

## Contract change request / Questions

- **Proposal (stats.ts, not changed here): a minimum-attempts threshold for SRS.** In syllable
  sessions, 74–78% of practiced bigrams had fewer than 5 attempts, and 88–94% of those had their
  interval grow from one or two clean attempts. I propose that `foldKeyAggs` call `scheduleSrs`
  only when the session had at least `ADAPTIVE_CONSTANTS.unseenAttempts` (5) attempts on the key
  or bigram, and otherwise keep the old `srs`. Keys almost always reach 5, so in practice this
  only affects bigrams.
- **Proposal (stats.ts): slower forgetting for `recentErrRate`.** Over a session, α = 0.1 per
  attempt keeps only about 20% of a key's history after 15 attempts. So the error signal is
  mostly the last session, which is noisy at 7–15 attempts per key. This is why only about a third
  of single runs get exactly `{a, ;}` as their top-2. α ≈ 0.05, or blending in the lifetime
  `errors / attempts`, would steady it. Changing α changes the stats fixtures, so I left it.
- **Question: latency in `letters` drills.** Latency is measured within a target, and `letters`
  targets are one char long, so the only latencies a key gets are its retypes after mistakes.
  Those include the notice delay, so one slip marks the key "slow" until 30 more such samples
  arrive (docs/sim.md finding 1). Options: (a) measure latency from the previous keystroke in the
  session when the target is a single char (contract §3.3 wording change); (b) have `keyWeights`
  ignore slowness when a key has fewer than N latency samples. I lean to (a). Sprout's early
  lessons are letters drills, so this matters for M3.
- **Proposal (adaptive.ts, M1-05 reviewer's idea):** let `keyWeights`/`scheduleSrs` take an
  optional constants override, so the sim can run a grid without patching the exported object.
  I ran the grid with a throwaway script that patched `ADAPTIVE_CONSTANTS` at runtime; nothing of
  it is committed.
- **Question: put `tools/sim/typist.ts` in the pure zone?** It is pure. Tests check its source for
  clock and randomness use, and check that it imports only `src/engine` and `src/types`. It is not
  in the `.oxlintrc.json` pure-zone list, because that file isn't mine. Adding one line there
  would let Oxlint and check-boundaries enforce it.
