# M2-05 FX: particles, hit-stop, shake, float text

Status: done. Waiting for the required feel review.

## What changed

- `src/render/fx/index.ts`: `createFx(ctx, { rng, groundY?, maxParticles? }) → FxCore`. This is the real `FxApi` (`burst`, `hitStop`, `floatText`), plus `stats()` and `dispose()`. It plugs into M2-01's seam: `createSceneHandle(canvas, { …, createFx: (ctx) => createFx(ctx, { rng: createRng(seed).fork("fx") }) })`.
- `src/render/fx/particle-pool.ts`: the particle simulation, with no three.js and no DOM. Struct-of-arrays `Float32Array`s are allocated once. Live particles stay packed. When the pool is full, a new particle takes the slot of the one nearest its end. Gravity, bounce on a ground plane, spin, and fade by scale. All randomness comes from the `Rng` passed in.
- `src/render/fx/particles.ts`: one pooled `InstancedMesh` (512 instances, one draw call) of small Lambert cubes. A per-instance `iUv` attribute is backed by the pool's own array, so nothing is copied. A small `onBeforeCompile` patch makes each cube sample a random 4×4-texel square of its block's side tile. Each chip looks like a piece of the block.
- `src/render/fx/float-text.ts`: the DOM overlay for float text. It is `aria-hidden`, has `pointer-events: none` and sits right after the canvas. Each label is placed every frame by projecting its world point. It has a pool of 6 labels and reuses the oldest. Text goes in with `textContent` only. The label sits on the UI kit's plate (`--c-plate`, `--c-plate-text`), uses `--fs-lg × --text-scale`, and takes `--font-body` for a single letter and `--font-pixel` otherwise.
- `src/render/fx/tuning.ts`: every feel number in one place for the review, plus `breakShake(streak)`.
- `tests/unit/dom/fx.test.ts`: 26 tests. They use a fake rAF, a real `createLoop`, a real camera rig and a seeded Rng.
- Outside Owns, needed so the feel review can see the effects:
  - `src/dev/scene-preview.ts` passes `createFx` and adds `vtScene.fx`, `vtScene.chip(letter)` and `vtScene.breakBlock(streak, count?)`. It also adds a `?fx=1` keyboard demo: letters chip the ore target, Enter or Space breaks it, and Shift+Enter adds streak.
  - `tests/e2e/fx.spec.ts` has 2 tests in real WebGL. They check that the shader compiles, that a burst costs exactly +1 draw call, the label fonts, that the loop idles once effects die, and reduced motion. No screenshot baselines.

## Decisions

- **Feel numbers** (all in `tuning.ts`):
  - chips are 0.14–0.22 of a block, live 600–1200 ms and shrink away over the last 45% of their life;
  - outward speed 2.6 u/s, lift 3.4 u/s, gravity 16 u/s²;
  - bounce keeps 35% of vertical speed, and horizontal speed and spin keep 60% per hit;
  - at most 40 particles per burst, whatever `count` asks for;
  - new chips grow in from half size over 60 ms, so a burst pops instead of blinking in.

  Nothing flashes: no color or brightness changes and no full-screen effects. Opacity changes only on float text, as one fade in and one fade out.

- **Shake stays on the camera rig** (`CameraRig.shake`, M2-01's trauma model as the card asks). `FxApi` has no shake. `breakShake(streak)` gives the size for a block break: intensity `0.12 + 0.012 × streak`, capped at 0.3, for 220 ms. At the cap the view moves at most 0.3² × 0.3 ≈ 0.03 world units. Reduced motion makes the rig's `shake` a no-op.
- **Hit-stop is capped at 120 ms** (`MAX_HIT_STOP`). Anything longer reads as a hitch, and PLAN §3.4 asks for 40 ms. Particles also hold still during a hit-stop (the loop only freezes mode subscribers), so the break lands before the chips fly. Float text keeps moving.
- **Ground** defaults to the bottom of the burst point's cell (`at.y − 0.5`), so chips from a broken block land where it stood. `createFx(ctx, { groundY })` can override it. Chips that fly past the edge of a pedestal settle at that height in mid-air and shrink away within about a second. A per-column ground lookup is possible later if the review minds it.
- **Reduced motion:** at most 6 particles, at 35% of the speed and 60% of the lift, gravity 5, no spin and no bounce: they drift down, settle and shrink. No hit-stop. Float text fades in (15% of its life) and out in place, with no rise and no pop, and lives 1100 ms instead of 900 ms. The flag is read on every call.
- **Single letters use `--font-body`** (Atkinson), following the M2-08 decision. "Single" means one grapheme after trimming (`Intl.Segmenter`). Each `var()` has the token's own stack as a fallback, so pages without `tokens.css` (the dev page) still get the right family.
- **Atlas texture:** the particle material's `map` is the scene's current `atlas().texture`, re-read on each burst (so it follows a biome swap) and never cloned or disposed here. Before an atlas exists, chips are untextured soft grey.
- **No per-frame allocation** in the particle path: preallocated typed arrays, reused `Matrix4`/`Vector3`/`Quaternion`/`Euler`, and a uv attribute that shares the pool's array. Float text writes style strings, but only while a label is alive.
- **Idle loop:** FX is one loop system that returns `true` only while particles, labels or a hit-stop hold are alive. `burst` and `floatText` call `loop.wake()` only when they actually spawned something.
- **Instance buffers:** `DynamicDrawUsage` with `frustumCulled = false`, and `visible = false` when empty, so the scene's draw-call count is unchanged while nothing is alive.

## Notes for downstream tasks

- **M2-10 (app shell):** pass `createFx: (ctx) => createFx(ctx, { rng: createRng(seed).fork("fx") })` to `createSceneHandle`. Under `?freeze` use the fixed seed, so screenshots are deterministic. `FxCore.stats()` (`particles`, `maxParticles`, `floatTexts`, `holding`) can go on `__vt`.
- **M2-13 (Mine mode):**
  - Per correct char: `fx.burst(target, { blockId, count: 3, speed: 0.5 })`.
  - On a break: `fx.hitStop(40)`, `fx.burst(target, { blockId, count: clamp(8 + 2 × len, 8, 30) })`, then `const s = breakShake(streak); camera.shake(s.intensity01, s.durationMs)`. Remove the block at the same moment, because chips spawn inside its volume.
  - `floatText(at, t("…"))` for kid-facing words; the caller translates.
  - **Never call any FX for a wrong key**: no burst, no shake, no hit-stop. The card's wobble and soft thud are the whole response.
  - `vtScene.chip` and `vtScene.breakBlock` in `src/dev/scene-preview.ts` show these calls.
- Float text needs the canvas to have a parent element. Otherwise `floatText` is a no-op. The overlay uses the canvas's `offsetLeft`/`offsetTop`, so it lines up with any positioned container.
- `fx.test.ts` builds a fake `WebGLRenderer` with `Object.create(prototype)`, because FX never calls the renderer. If a later change makes FX use it, that test harness needs a real stub.
