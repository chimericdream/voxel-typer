## The island data shape: confirmed, no contract change

`Profile.island` stays as contracts §15 has it:

```ts
island: { grid: ReturnType<VoxelGrid['toJSON']>; expansions: number; lastEdited: EpochMs } | null;
```

- **`grid`** is always 48×32×48 (`ISLAND_MAX`). Expansions unlock more of it; the grid never grows. The run-length encoding makes the air cheap: a new island saves as about 1,050 `rle` numbers (2.7 KB of JSON).
- **`expansions`** is a count, and a count is enough. A ring's terrain is written into the grid when the ring is added, so a load never regenerates it and doesn't need to know which biome each ring came from.
- **`lastEdited`** changes to the caller's `now` only when something changed since the island was opened (or last saved).
- **Inventory** stays in `Profile.inventory`. The editor works on a copy. M4-07 writes `editor.inventory()` and `editor.save(now)` back together, in one `store.save`.
- **Undo** lives in memory only. It is never saved.

## Conservation (the definition the property test checks)

For every block id `b`:

```
inventory[b] + (number of grid cells holding b)
```

is the **same before and after every `place`, `remove`, `stamp` and `undo`**. Inventory counts never go below 0.

- `place` moves one block from the inventory into an air cell.
- `remove` moves the block in a cell back into the inventory.
- `stamp` does both: it spends a block for each cell it writes and refunds each block it replaces.
- `undo` reverses the last edit exactly, grid and inventory both. Edits undo newest first, so an undo can never drive the inventory negative.

**Starter terrain is a gift, not inventory.** `createIsland` and `expand` are the only things that change the totals, because they add terrain. Generated blocks count as island blocks from then on, so **digging up starter grass puts 1 grass in the inventory.** That follows "nothing destroys blocks permanently", and it lets a kid dig a pond and use the dirt. It also means inventory totals can grow by digging. See the M4-09 and achievements notes below.

Flowers (`shape: "sprig"`) are ordinary blocks here, and the property test's block pool includes two of them.

## The API (`@/engine/island`)

```ts
ISLAND_MAX = { sx: 48, sy: 32, sz: 48 }; PLOT_SIZE = { sx: 24, sy: 16, sz: 24 };
RING_WIDTH = 2; MAX_EXPANSIONS = 6; UNDO_LIMIT = 50;
type IslandSave = NonNullable<Profile["island"]>;

islandBlocks(defs: readonly BlockDef[]): IslandBlocks          // id ↔ num lookup over the registry
islandSeed(profileId): number                                   // hashString(`island:${profileId}`)
createIsland(profileId, blocks, now): IslandSave                // the starter plot
openIsland({ island, inventory, blocks, profileId }): IslandEditor   // throws RangeError on a bad grid
footprint(expansions): { x0, x1, z0, z1 }                       // unlocked columns, half-open
inBuildArea(expansions, x, y, z): boolean
ringPalette(biome, blocks): RingPalette
countBlocks(grid, blocks): Record<BlockId, number>

type IslandCommand =
  | { kind: "place"; x; y; z; block: BlockId }
  | { kind: "remove"; x; y; z }
  | { kind: "stamp"; x; y; z; blueprint: VoxelGrid };   // blueprint (0,0,0) lands at (x,y,z)

interface IslandEditor {
  readonly grid: VoxelGrid; readonly expansions: number; readonly footprint: Footprint;
  readonly undoDepth: number; readonly dirty: boolean;
  inventory(): Record<BlockId, number>;
  preview(cmd): EditResult;   // dry run, e.g. to show what a blueprint still needs
  apply(cmd): EditResult;     // all or nothing
  undo(): boolean;
  expand(biome: BiomeId): boolean;
  save(now: EpochMs): IslandSave;
}
type EditResult =
  | { ok: true; changed: number; delta: Record<BlockId, number> }   // + refund, − spent
  | { ok: false; reason: "out-of-bounds" | "occupied" | "empty" | "unknown-block" | "not-enough" | "nothing-to-do";
      missing?: Record<BlockId, number> };                           // with "not-enough"
```

### Stamp rules

- Only the blueprint's **non-air** cells are written. Blueprint air leaves the island alone, so a house stamped onto a bump keeps the bump inside it. Blueprints should include their floor.
- A cell that **already holds the same block** is skipped, and it costs nothing.
- A cell that holds a **different block** is replaced. The old block goes back to the inventory, and that refund counts toward the stamp's cost: the stamp is checked on its net change per block.
- **Partial overlap with the edge:** if any non-air cell would land outside the build area, nothing is written (`out-of-bounds`). Blueprint air may hang over the edge.
- If the stamp wouldn't change a single cell, it is refused with `nothing-to-do`, so it never creates an empty undo step.
- When the inventory is short, the result is `not-enough` with `missing` per block id, and nothing changes. `preview` gives the same answer without applying the stamp.

## Decisions

- **The plot has its own small layout, using the Meadow recipe's blocks.** `generateDiorama` needs at least 32×21×40 and builds a Mine stage, so it can't make a 24×16×24 plot. `island.ts` uses `recipeFor("meadow")` for its blocks and sub depth, plus the shared `fbm2` noise and the tree, rock and flower templates. The layout: ground at 3–5, a flat 10×10 clearing in the middle with nothing generated on it, a small pond in one corner, two oak trees in two other corners, a rock in the last corner and up to 6 flower patches. Everything stays inside the footprint and below y = 16.
- **Rings are 4 cells per side, so each one makes the island 8 wider: 24 → 32 → 40 → 48.** That makes 3 expansions the maximum (see Questions).
- **A ring's terrain comes from the same height field as the plot,** so the ground stays continuous across the join. Each ring gets that biome's top, sub and deep blocks, sprigs on about 8% of columns and rocks on about 1.5%.
- **How the ring palette falls back:** `ringPalette(biome)` takes `recipeFor(biome)`, which already falls back to the Meadow recipe for a biome that has no worldgen. Any block of that recipe that the registry doesn't know falls back to the Meadow block for the same slot. If none of the flowers are known, the ring gets no sprigs. Today every biome gets Meadow terrain. When a biome registers a `DioramaRecipe`, its rings use that recipe with no change here.
- **`expand` can't be undone, but it keeps the undo steps.** They never touch ring cells, because those were outside the build area before.
- **Inventory keys stay listed at 0** when a kid places their last block of a kind, so the inventory screen (M4-09) doesn't turn that block back into a "?" silhouette.
- **An over-range `expansions` value in a save** (the validator only checks it is an int) is kept as saved, so the round-trip stays exact. The footprint clamps it to 0–3.
