## Decisions

- **The rules that need more than `inPlay` read optional ctx fields, each off by default.**
  `undo: true` turns Ctrl+Z or Cmd+Z into `typed` `'Undo'`, `band: 'sprout'` turns `` ` `` into
  `hearAgain`, and `wantsEnter: true` turns Enter in play into `typed` `'Enter'`. A caller that
  passes only `{ inPlay }` gets the plain §9 behaviour.
- **In play, Space, `'`, `/`, Backspace and Tab are always prevented**, including repeats and
  ignored chords (for example Ctrl+`/`). Without this, a child who holds Space would scroll the
  page, and a held `'` or `/` would open Firefox quick-find. This matters for "sticky" typists
  (PLAN §4.6). The one exception is IME composition: nothing is prevented while `isComposing`, so
  the IME keeps working.
- **Nothing is prevented in menus.** Tab focus and Enter on buttons keep their browser defaults.
- **Printable means one code point**, the same unit the engine matches on. C0 and C1 control chars
  and DEL are rejected. Non-ASCII chars such as `é` and emoji pass, and the engine decides whether
  they match.
- **Sprout `hearAgain` checks `key === '`'`, not `code === 'Backquote'`**, because the Backquote key
  types other chars on some layouts (`²` on AZERTY).
- **Undo is plain Ctrl+Z or plain Cmd+Z** (Meta+Z with no Ctrl, Alt or Shift), per the
  orchestrator's ruling. Ctrl+Shift+Z and Cmd+Shift+Z are not redo and stay ignored, as do
  Ctrl+Cmd+Z and repeats.
- **Typed keys are delivered in menus as well**, so a screen can use letters or Backspace if it
  wants them. Control mapping (Escape, Enter, Tab) differs by `inPlay` as §9 says.
- **Escape, F1 and the arrows are not prevented in play**, because §9 does not list them.
- **Timestamps come from `clock.now()`**, called once per keydown, blur or hidden event.
  `e.timeStamp` is not used.

## Notes for downstream tasks

- **M2-10 (app shell):** pass the full `InputCtx` from `getCtx`: `band` from the active profile,
  `undo: true` while Builder mode runs, and `wantsEnter` from the mode, if one ever declares it.
  `getCtx` runs on every keydown, so keep it cheap.
- `typed` keys can be `'Undo'` and `'Enter'`, as well as one char or `'Backspace'`. The engine
  ignores both (it accepts only one char or Backspace), so route `'Undo'` to the Builder mode
  rather than relying on that.
- `pause` arrives on every window blur and every hide, including while already paused or in a
  menu. Make the pause handler idempotent.
- F1 may open browser help in some browsers. The shell can call `preventDefault` on it if that
  turns out to matter.
- Under `?freeze`, contracts §13 says input timestamps stay real. Pass `realClock` to
  `attachKeyboard`, not the frame loop's fixed-step clock, or keydowns will shift the frames.
- `capsLockOn(e)` reads the event's state. Call it per keydown for the hint banner; there is no
  stored state.
- happy-dom's `getModifierState` always returns false for `CapsLock`, and returns `altKey` for
  `AltGraph`. The tests override it on each event (see `key()` in the test file).
