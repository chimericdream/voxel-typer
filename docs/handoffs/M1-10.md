# M1-10 Word-list pipeline

Status: done

## What changed

- `src/content/wordlists/loader.ts` (new, pure): `parsePoolText` splits a list file into tags, items, comment lines (all with line numbers) and structural issues, and never throws. It ignores a leading UTF-8 byte-order mark. `poolFromText(id, text)` builds a `WordPool`. `poolsFromTexts(texts, ids)` builds the registered pools and throws if a `.txt` file isn't registered or a registered id has no file. Both Vite's raw glob and `node:fs` reads feed it.
- `src/content/wordlists/pools.ts` (new, pure zone, Vite only): `POOL_IDS` is the append-only registry, one id per line. `wordPools` comes from `import.meta.glob(["./*.txt", "!./blocklist.txt"], { query: "?raw", import: "default", eager: true })`.
- `src/content/wordlists/sight-dolch.txt` (new): 279 Dolch words of 1–5 letters, `band=sprout reading=dolch`.
- `src/content/wordlists/home-row.txt` (new): 43 authored words that use only `a s d f g h j k l ;`. Tags: `band=all reading=grade2 keys=asdfghjkl; biome=meadow`.
- `src/content/wordlists/blocklist.txt` (new): the safety filter. It has 545 terms in categories: ip, brands, profanity, slurs, sexual, predation, self-harm, extremism, violence, scary, sensitive, unkind, drugs, gambling, slang. Each category has a whole-word section, and most also have a `strict` (substring) section. A final `allow` section holds 19 ordinary words that an inflection of a term happens to spell. The comment header explains that it is a safety filter, how matching works, and that the strict default stays until M6-08.
- `src/content/wordlists/README.md` (new): a guide for content authors (add a list in four steps, file format, tags, checks, blocklist rules, how code uses the pools).
- `src/content/wordlists/SOURCES.md` (new): where each list came from (Dolch is public domain, 1936/1948; home-row is authored), and every word left out with the reason.
- `tools/validate-wordlists.ts` (new): the validator. Run it with `npm run tool -- validate-wordlists [--dir DIR] [--blocklist FILE]`. It prints `file:line: message` and exits 1 on any problem. CI's `content` job already picks up `tools/validate-*.ts`. Matching covers inflections, look-alike spellings and comment lines (see below).
- `tests/unit/content/wordlists.test.ts` (new): runs the validator over the shipped lists through the API and the CLI, then on seeded bad fixtures. It also tests the registry against the files, the home-row key set, blocklist matching (inflections, look-alikes, and a list of 60 harmless look-alike words) and the loader.
- `tests/fixtures/wordlists/{bad,tags,registry}/` (new): seeded bad lists. Each breaks one rule on a known line. `bad/inflected.txt`, `bad/disguised.txt` and `bad/comment.txt` cover the review fixes.

### Child-safety review fixes (review 5864748324)

- **B1, inflections:** whole-word terms now also match their common forms. The matcher generates them by spelling rule (`inflections()` in the tool): `-s`, `-es`, `-ed`, `-ing`, `-er`, `-ers`, `-y`, `-man`/`-men`, consonant doubling, e-dropping, `ie` → `ying`, and `y` → `ies`/`ied`/`ier`. Terms with spaces inflect on their last word. Every example from the review is pinned in the test "matches inflections and derivations of whole-word terms" and in `bad/inflected.txt`, along with 11 more of my own. The review's compound form is now a profanity term, along with three other common compounds.
- **B2, missing categories:** new sections, each with a short category header:
  - child sexual abuse, predation and abduction
  - more sexual terms and body parts
  - self-harm and suicide, including acronyms
  - extremism and atrocities
  - more violence and weapons

  Every term the review suggested is included. The strict suicide and terror stems now cover their bare words. The predatory sense of "groom" is left out on purpose: a word filter can't tell it apart from grooming a pony, so that section's header says human review covers it.

- **Comments:** comments ship in the bundle, and a `?raw` import can't strip them without a build plugin. So the validator now checks every comment line against the blocklist and for non-ASCII, and the README tells authors never to name a left-out word in a comment. This check caught the Dolch and home-row headers, which named left-out words. Both now point to SOURCES.md.
- **Look-alikes:** a second matching pass splits on spaces and trims punctuation from the ends of each word. Inside a word it maps `1`→`i`/`l`, `3`→`e`, `4`→`a`, `0`→`o`, `5`→`s`, `7`→`t`, `@`→`a`, `$`→`s`, `!`→`i` and `|`→`l`, and removes other punctuation. Then it runs the same checks. Plain digits in sentences ("I have 3 cats", "Room 101") stay clean (tested).
- **Non-blocking notes 3–7 from the review, all done:**
  - The non-ASCII and blocklist checks run even when a file's tags are broken (tested with `tags/d-no-band.txt`).
  - The loader and the blocklist parser strip a leading BOM.
  - The suggested IP, character, brand, slang, drug and gambling terms are added, and `alexa` is now a whole-word term.
- **False-positive check:** I ran the new matcher over the 20,000 most common English words. The frequency list is public; I downloaded it for analysis and didn't commit it. Most words hit only through a derived form were meant to be blocked, but the run found real collisions:
  - Those went into the `allow` section (brass, butter, assess…, striped, blazer, hanger, spicy, baby, …).
  - Two strict terms became whole-word, because they hide in "saltwater" and "debugger".
  - The harmless look-alike test list grew from 32 to 60 words, and all pass. `crack` is out of that list, because the review asked for it to be blocked.

## Decisions

- **Tags on a `WordPool`:** `band` goes into `WordPool.band`. `tags` holds every other tag as `name=value`, in this order: `kind=…` and `case=…` (defaults filled in), then `reading=…`, then the rest as written. "Pools tagged with the biome" (contracts §6) therefore means `tags.includes("biome=<id>")`.
- **Tag names are a closed set** (`band reading kind case keys biome theme`), so typos fail. `reading` levels are PLAN §7.1's `dolch cvc grade2 grade4 grade6+`. Fry lists are not used: their copyright status is unclear.
- **`band=all` uses the Sprout word length (1–5)** and must use an early reading level (`dolch`, `cvc` or `grade2`), because Sprouts see it. Lists for `sprout` follow the same reading rule (PLAN §2).
- **Cross-pool duplicates compare by exact `band` value.** `all` is compared only with `all`, so `home-row` (`all`) may share words like `had` with `sight-dolch` (`sprout`). Otherwise every keyset list would have to drop the Dolch words.
- **Char sets by kind:** words use letters only, phrases add space and `'`, and sentences add digits and `. , ! ? ' " : ; -`. `case=lower` (the default) forbids capitals. `keys=` narrows the set further (spaces stay allowed).
- **Blocklist matching:** every term matches whole words and their inflections, and a term with spaces matches those words in a row. The forms are generated from each term, so the list holds only base words. The `allow` section cancels unwanted generated forms word by word, but never an exact term match. A `strict` section also matches inside a single word, never across spaces. Terms that hide inside harmless words are whole-word only, and a test pins the harmless look-alikes.
- **Comments are checked, not stripped:** stripping them needs a Vite plugin or a build step, and the card asks for none. The validator's comment check gives the same safety.
- **Dolch omissions:** a few Dolch words, and every word longer than 5 letters, were left out. SOURCES.md lists them, so a later Miner list can add the long words.
- **Registry parsing in the tool:** tsx can't evaluate `pools.ts` (no `import.meta.glob`), so the validator reads `POOL_IDS` from its source with a small regex. The test checks that this matches the real import.
- **`// oxfmt-ignore` on `POOL_IDS`:** without it oxfmt joins the array onto one line. That breaks the "one line per pool, append only" rule (contracts §0) and would make parallel list PRs conflict.

## Notes for downstream tasks

- **M3-02 / M5-05 (biome lists):** follow `src/content/wordlists/README.md`. Add `<id>.txt`, append the id to `POOL_IDS`, add a SOURCES.md section, and run `npm run tool -- validate-wordlists`. Sentence lists need `kind=sentences case=mixed`. Tag biome lists `biome=<id>` so lessons find them by default. Never name a left-out word in a list comment: comments ship and are checked.
- **Dolch words longer than 5 letters** (always, because, together …) are listed in SOURCES.md for a `band=miner reading=dolch` list.
- **M1-06 (generator) / M3-01 (curriculum):** import `wordPools` from `@/content/wordlists/pools` (Vite), or use `poolsFromTexts` from `./loader` with `node:fs` (tools). `src/content/index.ts` (orchestrator-owned) doesn't re-export the word lists yet. Adding `export * from "./wordlists/pools";` there is a one-line orchestrator change if wanted.
- `parsePoolText` returns line numbers, so other tools (e.g. a curriculum validator) can give file:line messages.
- **Strict default:** the blocklist errs hard on excluding. It blocks some everyday words in kid content (`kiss`, `hit`, `beat`, `ghost`, `monster`, `sword`, `god`, `vote`, `hospital`, and now `crack`, `poker`, `execute`). Inflection makes it stricter still: "hanging", "beating" and "voter" are blocked too. The orchestrator accepted this, and the owner can loosen it at the M6-08 content read-through (README.md and SOURCES.md say so).
- **Not caught, on purpose:** a word split by a space ("sh it"). Joining short fragments would flag ordinary phrases like "has hit", so reviewers of sentence lists (M3-02, M5-05) should watch for it. The predatory sense of "groom" isn't caught either (see B2 above).
- **Builder "code-ish" text:** `execute`, `execution` and their inflections are blocked (violence). A code-flavored list that needs "execute" would have to make the case for an exception at M6-08.
- **Adding terms:** a short new whole-word term can collide with common words through its inflections. When adding terms, run the matcher over a word-frequency list the way the review fix did, and allow any harmless collisions.
