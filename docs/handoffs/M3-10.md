# M3-10 Achievements framework and v1 set

Status: done (rework after review 5870859776)

A child now earns badges as they play. There are 24 in v1. Each one has a name, a short line, an
icon from the block registry and a pure `check(ctx)`. A "New badge: …!" toast shows once Results
or the next menu has been on screen for 1.5 s, one badge at a time, never during a lesson. **My
Badges** (route `achievements`) lists them all and is reached from the World Map's action bar.

## Decisions

- **Unlocks live in `Profile.achievements`** (id → first unlock time). `withUnlocks` never
  overwrites an earlier time, and nothing re-locks. Unknown ids in a save (older or newer builds)
  are kept and ignored by the screen.
- **When badges are checked:**
  - **At the end of each session,** on the profile after the session is folded in, so "First
    Steps" counts the lesson just played. This happens in the same autosave.
  - **During play, live checks** cover the 5 badges that only read engine events (`live: true`).
    A check is scheduled 600 ms after a `targetComplete`, `streakBroken` or `paused` event, and is
    pushed back by each new one, so it never runs inside a keystroke. Plain `streak` events (every
    key) don't schedule one.
  - **A lesson left early** keeps the live badges it earned, added to the app's current profile.
    Nothing else about the lesson is saved.
- **The placement test counts for typing and finding badges, not for lesson badges.** The tracker
  counts a lesson only if its id is in the curriculum, so the placement lesson never gives "First
  Steps", "Not One Slip" or a biome badge. Tested-out lessons (`plays: 0`) don't count toward a
  biome badge. Its loot goes into `found`.
- **When toasts show:**
  - They wait through running, pause and break, because the pause screen is a `showModal()`
    dialog that hides the rest of the page from screen readers. So decision 76 holds.
  - On a new screen they wait 1.5 s, so the screen's own announcement is read first (B1).
  - I didn't make `announce` queue messages. That would change the kit for every caller and
    needs the orchestrator; the settle delay fixes B1 without it.
- **Early Bird is hidden, and counts from 6 am to before 9.** It shows as a surprise so no child is
  nudged to wake early for it.
- **Three Good Days counts any 3 days, not a streak,** so missing a day never costs anything.
- **Calm Minute caps each pause between keys at 5 s,** so a long pause can't fill the minute, and
  a slow, careful typist still gets credit for every key.
- **The definitions are lazy-loaded** by the shell (`import("@/content/achievements")` at start,
  tracked by `whenReady`), to keep the block registry out of the first bundle. If a lesson
  finishes before they load, the next session catches up on every profile-based badge. Early Bird
  and the live badges can't catch up.
- **Biome badges keep the ids `<biome>-master`,** matching the `meadow-master` already in the
  `veteran-builder` fixture.

## Contract change (approved by the orchestrator, additive)

`src/save/schema.ts`, `Profile` (contracts §15), after `inventory`:

```ts
/**
 * Blocks ever found in play (lesson and placement-test loot), per id. Never lowered by building
 * or digging, and island digging never adds to it. Added 2026-11-12 (M3-10, additive): a save
 * without it is read as a copy of `inventory`, which was exact while only loot reached the
 * inventory (`foundBlocks` in `src/engine/achievements.ts`).
 */
found?: Record<BlockId, number>;
```

- `applyResult` and `applyPlacement` write `found: addLoot(foundBlocks(profile), result.loot)`.
  Nothing else writes it. The island editor (M4-07) must not.
- `foundBlocks(profile)` (`src/engine/achievements.ts`, pure) returns `profile.found`, or a copy
  of `profile.inventory` for a save without it. There is no migration and no version bump.
- The validator accepts `found` as optional (`recordOf(int())`). A mistyped one fails.
