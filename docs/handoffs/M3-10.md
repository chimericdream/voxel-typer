# M3-10 Achievements framework and v1 set

Status: done

A child now earns badges as they play. There are 24 in v1. Each one has a name, a short line, an
icon from the block registry and a pure `check(ctx)`. After a lesson, a "New badge: …!" toast
shows at the top right, one at a time, on Results or the next menu, never mid-word. **My Badges**
(route `achievements`) lists them all.

## What changed

- `src/engine/achievements.ts` (new, pure): `AchievementDef`, `AchievementContext`,
  `EventAggregates` and `createEventAggregator` (folds engine events), `newlyUnlocked`,
  `withUnlocks`, `localHour`, `localDayNumber`. It never reads the clock: the session's start time
  and the time-zone offset come in as data (`ctx.when`).
- `src/content/achievements/{progress,typing,collect}.ts` (new, pure) hold the definitions.
  `index.ts` (new) aggregates them in screen order and exports `achievementById`.
- `src/i18n/en/achievements.ts` (new) holds all the copy, plus one line in `src/i18n/en/index.ts`.
- `src/ui/screens/Achievements.tsx` + `.module.css` (new): My Badges. Earned badges are bright and
  say "Got it!"; the rest are soft and say "Not yet". A hidden badge shows as "Surprise badge"
  until earned. Back has focus, and Escape goes back. The list is a focusable scroll area (axe
  `scrollable-region-focusable`). One line in `src/app/routes.ts` (appended).
- `src/ui/components/AchievementToast.tsx` (new): the queue view, one badge at a time for 3.5 s,
  through the kit `Toast`. The kit Toast reads the text out in the page's live region, outside
  `#app`. The pop-in uses the shared `--motion-ok` flag, so with reduced motion it just appears.
  `BadgeIcon.tsx` + `Badge.module.css` (new) draw the block icon, the same way as the Results loot.
- **Outside "Owns"** (small and additive, needed to wire it in):
  - `src/app/achievements.ts` (new): the impure tracker. It captures the start time and
    `getTimezoneOffset()`, listens to the run's bus, runs the debounced live check and evaluates
    everything at finish.
  - `src/app/play-host.ts`: an optional `achievements` dependency. `start` begins a run tracker on
    the run's bus. `finish` passes the `applyResult` profile through `tracker.finish`, so the
    unlocks are saved in the same autosave. The stale-save guard (`if (run !== r) return`) is
    unchanged. If a lesson is left early (`teardown` of an unfinished run), the live unlocks it
    already earned are saved, and only those.
  - `src/app/shell.ts`: builds the tracker and loads the definitions lazily (see the size note),
    adds `badgeToasts` (signal) and `nextBadgeToast()`, and takes an optional `tzOffsetMin` dep.
  - `src/app/App.tsx`: `<Badges>` lazy-loads the toast with the first badge, and keeps it closed
    while a lesson is running, paused or on the break overlay.
  - `tests/e2e/slice/baselines.spec.ts`: the Results test now expects "New badge: First Steps!" and
    waits for the toasts to finish before its screenshot, so `results.png` is unchanged.
- Tests: `tests/unit/engine/achievements.test.ts`, `tests/unit/app/achievements.test.ts`,
  `tests/unit/ui/achievements.test.tsx`.

## Decisions

- **Unlocks live in `Profile.achievements`** (id → first unlock time), which is already in the
  frozen schema. No contract change. `withUnlocks` never overwrites an earlier time, and nothing
  re-locks. Unknown ids in a save (older or newer builds) are kept and ignored by the screen.
- **When badges are checked:**
  - **At the end of each session,** on the profile after `applyResult` folds the session in, so
    "First Steps" counts the lesson just played. This happens in the same autosave.
  - **During play, live checks** cover the 5 badges that only read engine events (`live: true`).
    A check is scheduled 600 ms after a `targetComplete`, `streakBroken` or `paused` event, and is
    pushed back by each new one, so it never runs inside a keystroke. Plain `streak` events (every
    key) don't schedule one.
  - **A lesson left early** keeps the live badges it earned, saved on their own. Nothing else about
    the lesson is saved.
- **The placement test counts for typing and finding badges, not for lesson badges.** The tracker
  counts a lesson only if its id is in the curriculum, so the placement lesson (M3-05) never gives
  "First Steps", "Not One Slip" or a biome badge. A biome badge needs every lesson really played
  (`plays ≥ 1`), so "tested out" lessons (`plays: 0`) don't count. A child who tests past Meadow
  can still earn its badge by playing it. Streaks, Word Maker, First Ore and the like do count from
  the placement run, because it is real typing. If M3-05 lands first, its `applyPlacement` branch
  only needs the same `r.ach?.finish(…) ?? applied` wrap.
- **Toasts never show while a lesson is on, paused included.** Pause is a `showModal()` dialog, so
  the page behind it is inert and a toast there would be hidden from screen readers. They wait for
  Results or the next screen instead. This is stricter than the brief's "or a pause in play". So
  no HUD message is ever displaced: decision 76 still holds.
- **Early Bird is hidden, and counts only from 5 am.** It shows as a surprise so no child is
  nudged to wake early for it. A session at 3 am doesn't count either.
- **Three Good Days counts any 3 days, not a streak,** so missing a day never costs anything.
- **Calm Minute caps each pause between keys at 5 s,** so a long pause can't fill the minute, and
  a slow, careful typist still gets credit for every key.
- **The definitions are lazy-loaded** by the shell (`import("@/content/achievements")` at start,
  tracked by `whenReady`). Loading them eagerly pulled the block registry into the first bundle
  (+3 KB gzip). If a lesson somehow finishes before they load, nothing unlocks that time, and
  the next session catches up on all profile-based badges.
- **Biome badges keep the ids `<biome>-master`,** matching the `meadow-master` already in the
  `veteran-builder` fixture. They cover the 4 biomes the card named (Meadow, Birch, Shore,
  Frosty). Each needs its biome to ship lessons; today only Meadow does.

  `live: true` only if `check` reads nothing but `ctx.events`.
