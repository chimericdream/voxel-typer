## Decisions

- **6 is the left index (L2), 7 is the right index (R2).** Touch-typing charts disagree on 6. Most kids' typing tutors put it on the left index, and it sits above the T/Y gap.
- **Rows hold only keys that type a char, plus Space.** `base` is required in §16, and Tab, Caps Lock, Shift, Enter and Backspace type no char. The `x` offsets follow real ANSI/ISO geometry (Q at 1.5, A at 1.75, Z at 2.25, Space at 3.75 with `w` 6.25; ISO's `IntlBackslash` at 1.25), so an on-screen keyboard can draw the modifier keys in the gaps.
- **`homeCodes` is `["KeyF", "KeyJ"]`**, following the comment in §16 ("KeyF, KeyJ get bumps"), not the whole home row.
- **The JSON is parsed into `unknown` and checked at import time** by `isLayoutDef`. A bad file throws `invalid keyboard layout: src/content/layouts/<file>` at startup. The guard also rejects a `code` used twice, a char on two keys, an unknown finger, a `base`/`shift` that isn't exactly one code point, and a home code missing from the rows.
- **Lookups use a char → key index per layout object**, built on first use and cached in a `WeakMap`. If a char is both a `base` and a `shift` somewhere, `base` wins; the guard rejects that case for the shipped files anyway.
- **AltGr chars (en-GB `€`, `¦` and so on) are not in the data.** §16 has no AltGr slot, and no lesson needs them.
- Multi-char strings, `""`, `\n` and `\t` return `null` from both lookups.

## Notes for downstream tasks

- **APIs beyond §16:** `EN_US`, `EN_GB`, `LAYOUTS` (en-US first), `layoutById(id): LayoutDef | null`, and `isLayoutDef(value: unknown)`. All come from `@/content/layouts` and the `@/content` barrel. `src/content/layouts/index.ts` uses plain JSON imports with no `import.meta.glob`, so tools can import it under `tsx`.
- **Matching stays on `KeyboardEvent.key`** (PLAN §4.5, M1-08). Use `codeFor(...).code` only to light up the on-screen key, and `shift` to light up a Shift key too (for a right-hand char, light the left Shift and the other way round).
- **The on-screen keyboard** draws modifier keys itself in the `x` gaps. ISO Enter (en-GB) is taller than one row; the data doesn't model it.
- **M1-07's typist (`tools/sim/typist.ts`) could switch to this data** in place of `QWERTY_ROWS` / `QWERTY_NEIGHBORS`. Import `EN_US` from `src/content/layouts`, look up the expected char with `codeFor`, then take as neighbors the keys whose centers (`x + w/2`, row index) lie within about 1.25 key units: the same row at ±1, and the rows above and below. Return their `base`, or their `shift` when the expected char needed Shift. That keeps uppercase-to-uppercase, adds the punctuation rows, and works for en-GB with no change. Build the map once per layout. I didn't edit the typist; this is a note only.
- Adding a layout (Dvorak, Colemak, AZERTY, QWERTZ): add `<id>.json`, import it in `index.ts`, pass it through `checked(...)` and append it to `LAYOUTS`. The structural test covers it automatically. Write the ASCII sweep for it on purpose, because AZERTY and QWERTZ need AltGr for some ASCII chars.
